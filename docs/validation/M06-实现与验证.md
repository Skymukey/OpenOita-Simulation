完整世界的材料/体/形状/变更计数逐参与者校验，不能相加重复计数；CPU保守合并状态、规则、结构、物理、空间、排开及准备峰值。规则按实际材料容量建立，增长先预留旧表与新表并存的工作集。空间缓存失效不会抹掉保留容量，重建前另行检查；接触宽阶段格对最多64N，完整输出最多8N，超限整拒不截断。排开搜索访问集按世界范围与曼哈顿半径交集估算。该账为容量控制，不能替代Profiler内存峰值证据，也不保证配置最大值能在256MiB内运行。

## 2. 正式运行路径

Create/Reset：严格三文件加载 → M02独立初态 → 全部结构分析 → M05全部材料/几何 → M06候选原生对象与四边界 → 联合预检/采用 → 初态精确空间与水汽覆盖检查 → 发布Tick0 → 显示服务Prepare。显示准备失败释放已取得的运行资源，工厂不返回世界。

Step：按令牌顺序执行命令 → 流动前采湿 → 水 → 蒸汽 → 采湿/灭火 → 燃烧 → 需要时M04/M05/M06结构事务 → D08规划 → 每子步M×g施力及独立场景Simulate → 候选速度/真实格边缘位移/边界/固体穿透校验 → 候选接触采湿 → 整批排开与位姿同一候选采用 → 排开后灭火 → 发布版本及隔离通知异常。自动阶段失败不发布成功Tick，最后提交快照保持；求解器不承诺回滚，恢复使用Reset。

精确几何使用同一组可表示格顶点进行SAT、边界和线段判定，AABB只筛候选。Spawn的正面积重叠直接按深度大于0判断，不能套用物理0.1×cellSize容差。同归属严格四邻接；跨归属按epsilon=1e-4×cellSize和最近特征判定，纯顶点接触不传播。水汽源按y/x，目的地按距离/y/x；原批源不能充当空目标，路径不能穿起止固体，全部意图成功后交原事务采用，保留完整状态与实例。

## 6. 发现并修复的问题与未测项

早期真实PlayMode暴露了两个生产问题：Unity激活最终Collider及simulated后会重建质量/运动，现改为全部生效后显式恢复mass/COM/inertia/v/omega；旧中心投影与float连续位姿生成了两套边界，初态共边被误判正重叠，现统一由实际顶点投影。另修复空间保留容量漏账、Record后ProjectedCount重复计数及释放后几何引用保留。未放宽自由落体、接触、穿透或Spawn阈值。

水/汽初态MoveCountdown为0，会先在规则阶段流走；物理首接触夹具通过原状态事务设置合法等待值，再由真实规则扣减。T7第二源无解使用流体封住邻格，避免额外固体角点提前引发另一类物理故障。以上调整夹具以准确触发目标验收，不改变生产规则。

未测/未完成：默认M07B显示与显示候选事务、完整ChangeSet、Game View实际像素读回、M02/M05/M07A全部联合出口、Windows Player与IL2CPP、64体P3和完整Step P2/P3/P4、GC=0及CPU/原生/GPU资源峰值。当前有界字典/数组/候选复制存在托管分配，不宣称稳态GC=0。三文件Schema、示例与默认数值没有变更，本轮不重复声明Schema或Player验收。隔离副本与过程日志留在忽略的Logs下，未批量清理。
