# M06-F01 水汽暂存与恢复：实现与验证

日期：2026年10月6日｜规格：[M06-F01](../specs/M06-F01-水汽暂存与恢复.md)｜公共合同1.10。

本轮已将正式世界的立即排开替换为整批暂存与最终阶段恢复，完成Editor功能回归及Windows64 Mono专项运行。没有合法恢复目标时保持Ready，完整状态和材料总量保留；真正资源故障仍冻结最后成功版本。本文记录实际结果，不把旧M06/M07/M08测试数量继承为新规则通过数量，性能和其他Player出口保持未完成。

## 实现范围

- M00：暂存记录、独立身份域/计数键、暂存/恢复变更原因、数量诊断及两个失败注入点。
- M02：记录及候选/提交副本的唯一所有权、完整状态与实例联合迁移、整Tick计数、材料/CPU预算、Reset及Dispose。
- M03/M06：活动水流不变；暂存移动周期暂停，蒸汽每Tick一次寿命更新；逐子步捕获覆盖，最终位姿下优先原格再四邻接恢复，没有空位继续Ready；恢复后采湿灭火。
- M07/M08：活动查询/命令不命中隐藏记录，显示清源及恢复目标，试玩窗口显示活动/体内/暂存/总量。场景保存仍为编辑初态。

记录保留完整状态、原坐标、进入Tick和稳定ID。水汽暂存不产生碰撞、浮力或压力；没有永久丢弃或隐式覆盖。固体间微穿透、速度、边界、真实资源故障的处理保持原合同。

## 配置、资源及复现

三文件/schemaVersion=1、默认值与范围未变；只同步Schema说明。新增文件均带Unity生成的.meta。初态与历史Player失败配置不被改写。验证控制配置仅写入本轮新构建目录，结束后已逐字节恢复当前正式三文件；ProjectSettings/EditorSettings和ProjectSettings也与本轮验证前副本逐字节一致，保留原有未提交设置。全部自建Player验证进程均已关闭，用户Editor仍停在原M05Preview编辑态。

复现控制Player：先备份本轮构建的三文件，将[暂存夹具](F01/Player暂存夹具/README.md)三文件放入构建的`OpenOita_Data/StreamingAssets/OpenOita`，用`-batchmode -force-d3d11 -openOitaValidateF01 -logFile <明确日志路径>`启动。每250Tick只读记录同版本数量，验证后恢复备份；不要覆盖项目Assets或其他已交付包。初始10格，刚体覆盖水后应持续Ready且总量10。该开关不增加推进器或修改物理配置。
