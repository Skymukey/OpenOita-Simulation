## 唯一绑定与容量

入口为 `OpenOita.Rules.RuleExecutionTable`。M02 在创建/重建时构造一份，调用 `Validate(M01的IRuleRegistry)`，并单独检查 M04 结构服务已具备。`TryGetExecutor` 仅为 LiquidFlow、GasDrift、Burnable 返回入口；Structure 归 M04，ExtinguishesFire 通过湿接触邻格能力查询，不新增逐格执行器。

`cellCapacity` 必须覆盖预定世界材料容量（主网格与全部体），至少1；容量不够时整批返回CapacityExceeded。默认每个执行器输出容量为N；水先生成并整链预留L01原子链，再处理余下五层候选，蒸汽保持五层移动，Execute已输出完整裁决计划。通用 `Movement.Resolve` 使用5N候选索引、N状态索引及一个N意图结果缓冲，避免复制5N份完整状态；调用方不能把未预留的竞争候选混入原子链后逐边淘汰，破坏已完成的整链裁决。

`contactCapacity` 是一次 QueryContacts 可容纳的完整接触记录数；默认 N，M06 必须确认返回的重复记录/特征数量上界。不足为 BufferTooSmall，输出批次或 WetInstances 均为空，不能把截断结果用于标湿。失败注入可直接降低各执行器的 `intentCapacity`、扫描容量或 `contactCapacity`，不需要修改公共合同。

所有成功批次只在下次同一执行器 Execute 前有效；Movement 的结果在下次 Resolve 前有效；WetInstances 在下次 Collect 前有效。调用者完成预检和复制/应用后才能复用对应缓冲。禁止重入及跨线程共用执行表；M02 保持公共主线程和阶段门禁。

`ReservedCpuBytes = N×3072 + contactCapacity×256 + 4096 + (88N+256)`（L01现行公式）为保守规则缓冲预算，不是真实峰值。构造时预留超出256MiB会在分配前拒绝；其他服务需由M02一起合并预算。N=65536、接触容量=N时规则预留为223875328字节（约213.504MiB），加默认状态缓冲至少52MiB已超过256MiB目标。当前尚无调用者将ReservedCpuBytes并入完整世界总账，正式装配前须统一预算并缩减工作集，不能把剩余预算重复分给状态、几何和物理。

## M02 阶段接线

1. 命令提交完成后开始 PreFlowContacts，调用 `WetContacts.Collect(snapshot, materials, instances, contacts, context)`。只有完整成功后由 M02 对 WetInstances 调用现有 `MarkWet`；规则自身只查实例和湿标记。
2. Water：调用 Water.Execute，预检并应用整个胜出移动/状态批次，使用移动后状态而非旧状态。更新阶段占据视图，保留原实例句柄。
3. Steam：读取水已提交的工作状态，调用 Steam.Execute。寿命到零的 Remove 原因为 LifetimeExpired，不再移动；其余完整移动/状态同批提交。
4. Extinguish：更新接触，再次 Collect，并向同一个实例表追加湿标记。执行 WetContacts.Execute，将 WriteState 全批预检并应用。湿集合一 Tick 只增加。
5. Burning：在灭火后的阶段视图执行 Burning.Execute，完整提交扣燃料、传播周期、Ignite 与 BurnedOut Remove。初始火 Tick1 可消耗；IgnitedTick 等于 workingTick 的新火本步不消耗或传播。湿格不会被传播重新点燃。
6. 对结构材料变化准备全部连通/材料体/几何/物理结果；逐子步的新增湿接触使用 Physics context 的 Collect → M02 MarkWet → Execute。此处灭火保留此前已经扣除的燃料。
7. 只有全部阶段/子步成功后发布版本、ChangeSet、令牌结果和通知。任何自动批次失败由 M02 Faulted，不提交半批、成功 Tick 或失败工作快照。

现有 `ITickInstanceMap` 对象在同 Tick 内必须保持稳定，移动/提取/拆分只迁移句柄；Replace 创建新句柄且不继承湿标记。新 Tick 才清空湿集合。
