## 冻结入口及调用责任

```csharp
// M02 WorkingWorld 持有唯一序列；内部受控方法。
WorldResult ReserveBodyIds(int count, Span<ulong> destination);

// M00 公共合同，绑定到上述方法；M05只消费预留结果。
public delegate WorldResult BodyIdReservation(int count, Span<ulong> destination);

// 原 IMaterialMutationPreparer 唯一签名，不保留旧重载。
PreparationResult<IPreparedMaterialMutation> Prepare(IWorkingWorldView world,
    StructurePlan structure, ReadOnlySpan<MutationIntent> resolvedChanges,
    BodyIdReservation reserveBodyIds, in TransactionContext context, IFailureInjector failures);
```

M02在每个WorkingWorld建构时持有一个IdentitySequence，从0开始；新BodyId从1分配。序列跨Tick和事务持续，候选复制/Abort/Dispose、发布和旧体撤销均不重置。新generation重建新世界可从1开始，旧回调绑定旧世界，释放后返回Disposed。入口限所属线程，Faulted/Disposed返回相应错误，且不写缓冲。

M05统计全部ExtractFreeGrid/CreateChildBody的数量，先预检已知预算，再一次预留全部ID并按StructurePlan的原归属、原最小y/x顺序消费；RetainFixedGrid为0，RetainBody保留原ID且不耗号。原体多分量全部新建并撤销旧体；删空只撤销。预留不创建材料体、不修改材料/实例、Tick计数和公开版本；M05计算核心仍消费数组，不持有分配器。

## 参数、容量及失败语义

| 条件 | 返回与状态 |
| --- | --- |
| count<0 | InvalidArgument；缓冲/序列不变。 |
| destination.Length<count | BufferTooSmall；不部分写入、不耗号。 |
| 正数量超过剩余ulong号段 | CapacityExceeded；不部分写入、不耗号。 |
| count=0，世界访问有效 | 成功；不写入、不耗号，序号耗尽时也成立。 |
| 故障、释放或错线程 | Faulted、Disposed或InvalidArgument；零数量也受门禁约束。 |
| 成功预留 | 仅写前count项，按上一ID+1至+count递增，尾部不变；从此号段不回收。 |
| 后续准备失败、预算拒绝或候选释放 | 已成功预留的号段仍消耗；重试取得后续新ID。 |

整段容量用 `count > ulong.MaxValue - last` 判断，先判断再加。ulong.MaxValue可作为最后合法ID，之后正数量全部失败，不能回到0。预留数不等于存活体数；最终体/形状/CPU预算仍由准备与统一事务检查。

示例：同generation已预留到7，体7删中格成两分量，得到8、9并在计划中撤销7；准备失败后再申请两项得到10、11。删端格仅剩一分量保留7且不耗号。
