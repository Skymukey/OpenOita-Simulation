## 给M05/M02的接入要求与剩余风险

1. M05直接消费 `Disposition` 与 `RetiredBodyIds`，不能重新推导另一套分类。每个自由分量都处理，包含单格；空体只撤销，多分量旧体撤销后为全部子体新建，单分量保持旧ID。
2. M02在Prepared租约中先调用PlanStructure，M05随后使用同一个 `CandidateWorld` 读取成员完整状态；M05/M06全部准备及预算预检成功后才Apply。计划键不延长候选/实例租约，候选不能充当公开快照。
3. **M02-I02仍待统一冻结**受控材料/归属写入、BodyId预留、实例和湿集合移交。本轮CONTRACTS1.2只解决结构计划和候选承载；它不能替代M05完整事务入口。M05可开始矩形、质量/惯量、速度继承及提取方案的纯计算开发，正式提交须落实该缺口。
4. 新增分量区间数组为有界O(N)托管工作缓冲；最终公共DTO仍按M00复制合同分配。M02已有每格640字节保守预留覆盖此次区间索引，但未实测完整CPU峰值/GC或性能阈值；M05/M06几何等仍须纳入统一总账。
5. 未测：正式Create/Step/Reset、真实体提取/拆分/速度/碰撞/查询/显示、T4-03预留失败不复用、20轮全系统资源、P2/P3/P4、Windows Player/IL2CPP。原因是M05/M06/M07A/M07B尚未装配，而非把测试桩当作完整验收。
