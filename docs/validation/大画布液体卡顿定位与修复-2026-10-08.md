# 大画布液体卡顿定位与修复（2026年10月8日）

状态：已确认主线程热路径并修改源码，当前Unity仍在执行旧代码且无法响应MCP；编译、Editor测试及正式地图回归待编辑器恢复后执行。不宣称修复已经运行通过。

## 已确认的根因

关闭默认CPU内存预算拒绝后，BasicSandbox的37251格初态开始进入正式规则计算；36867格为水，世界9600×6400。磁盘关卡水坐标范围x=13–1166、y=23–273，逻辑画布远大于材料实际范围。

Unity停止试玩请求因插件连接断开未成功。通过本项目主编辑器的Mono软调试端口读取托管栈，暂停采样后在finally恢复并断开，确认主线程链路：

```text
WorldHost.Update
FixedStepDriver.Advance
SimulationWorld.Step
WorldRuntime.CompleteTick / Run
LiquidFlowRule.Execute
MovementCandidateResolver.Phase.Generate
LiquidSpreadPlanner.PrepareHorizontal
LiquidSpreadPlanner.FindOutlet
LiquidSpreadPlanner.Landing
RuleBatchContext.Passable / ClearOfSolids
WorldOccupancyIndex.HasGridSolidOverlap
Dictionary<Vector2Int, Bin>.FindEntry
```

FindOutlet对每个可用方向逐列寻找更低落点，Landing又向下检查空列；原实现即使找到y=0仍扫描后续更远列。9600格宽画布上的无效搜索被大量水源重复触发，且默认自动驱动每帧最多补跑8个Tick，延长一次主线程阻塞。这是代码循环/工作量问题，不能解释为预算监测或GPU渲染问题。

## 源码修复

- LiquidSpreadPlanner.FindOutlet：找到landingY=0时提前结束当前方向。合法落点y不低于0；nextX按离源距离单调增长，后续列既不能更低，也不能赢得距离平局，所以最优出口和单格移动语义不变。
- FixedStepDriver.Advance：默认每帧最多1Tick，显式传入其他步数仍支持；积压时间保留，固定步长不变，不裁掉模拟时间。重负载可能落后于真实时间，单Tick本身的耗时仍需正式测量。
- 新增256/9600格宽、6400高、y=273三格支撑平台的一格水用例：验证最近最低出口方向、仅横移一格、水量守恒，且OutletProbes少于600。为RuleFixture添加可选宽度参数，原默认256保持。
- 新增Host默认一帧一Tick且保留积压时间用例；原显式2/8步驱动用例保留。
