# P2 标准规则压力地图（2026年10月8日）

## 产物与使用

- 场景：`Assets/Scenes/GC_P2.unity`。
- 独立关卡：`Assets/OpenOita/Maps/GC_P2.asset`。
- 在 Unity 打开该场景并进入 Play，正式 `WorldHost` 自动按 0.02 秒步长推进；左上角已有的“Reset地图”按钮恢复初态。
- 场景绑定正交摄像机、`OpenOita/ChunkDisplay` 和 `OpenOita/CommittedFlame`，关闭 Host 精确像素视图以完整展示地图。摄像机中心为 (12.8, 12.8)，正交半高 13.3。
- 仅创建资产和场景，未增加运行脚本、自动重置、采样脚本或公共接口，未调整模拟规则和资源预算。

**当前限制：世界可创建为 Ready，但第一次 Step 在空间索引预算预检失败并进入 Faulted，提交 Tick 保持 0。因此这张地图目前可以复现 P2 容量问题，尚不能持续推进以采集稳态 GC。**

## 标准负载

通过 Unity MCP 的内存内 C# 执行复用 `FixtureCatalog.P2()`，调用正式序列化、严格加载器及 `OpenOitaMapCreation.CreateAsset` 创建关卡；所有场景引用及 meta 由 Unity 生成。

世界为 256×256，cellSize=0.1，stepSeconds=0.02，seed=1；材料参数取现有 StreamingAssets 标准材料表，配置和布局与 P2 夹具一致。

| 内容 | 坐标范围（含端点） | 格数 |
| --- | --- | ---: |
| 固定混凝土 | x=0–255，y=0–3 | 1024 |
| 水 | x=0–127，y=4–67 | 8192 |
| 蒸汽 | x=128–191，y=4–35 | 2048 |
| 固定木头 | x=0–255，y=68 | 256 |

总材料11520格、固定标记1280个；木排偶数x的128格初燃。

## 实际验证

环境：Unity 6000.3.11f1 Windows Editor，正式地图/Host/显示链，经 OpenOita-Simulation 的 MCP 执行。本次不是 Player 性能验收。

| 项目 | 结果 |
| --- | --- |
| 严格配置加载、材料/固定/初燃数量 | 通过 |
| 关卡场景和配置与 P2 夹具规范化文本完全相同 | 通过 |
| 自动驱动、摄像机、两份生产 Shader 引用 | 通过 |
| Reset恢复 Ready、Tick 0、11520格 | 通过；generation从1增至2 |
| 第一次 Step | 失败：`CapacityExceeded / Preflight / spatialCpuBytes` |
| 失败后发布版本 | 保持 Tick 0，Lifecycle=Faulted |
| 初态显示 | 截图确认混凝土地面、左侧水块、右侧蒸汽、顶部木排及初燃火焰 |
| 前200 Tick及流水/蒸汽/燃烧演化 | 被第一次Step预算失败阻塞，未完成 |
| 退出Play后资产内容 | P2关卡SHA256不变，既有“新地图”SHA256不变 |
| 最终编辑器状态 | GC_P2场景打开、未进入Play、场景无未保存改动 |

错误原文：“空间索引重建前的保留及候选工作集超过统一CPU预算。”

Reset后Ready状态的内部保留CPU估算为169907552字节。首次Step失败后的内部保留估算为265262768字节；11520格空间索引重建估算为94375936字节，二者合计359638704字节，超过268435456字节（256 MiB）的统一上限。这些值是代码预算估算，**不是实际托管分配、GC堆大小或Profiler内存峰值**，不能据此声称发生了同等大小的GC。

证据保存在忽略目录 `Logs/GC-P2-20261008/`：`reset-step.txt`、`budget.txt`、`console.txt`、`final-asset-check.txt`、`GC_P2_Tick0.png`。Console读取到上述容量警告，未读取到编译错误。
