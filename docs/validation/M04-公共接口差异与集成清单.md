## M02 候选视图与调用要求

生产入口为 `OpenOita.Structure.ConnectivityAnalyzer`，实现既有 `IStructurePlanner`。构造参数 `cellCapacity/bodyCapacity` 由调用方确定，建议按配置的 `MaxMaterialCells/MaxDynamicBodies` 预留现有工作世界目录容量。分析器完整扫描全部归属，`changedCells` 只检查引用合法性，不作为裁剪范围；空变更集同样分析全部初态。

1. `OccupiedCells` 必须列出候选视图的全部非空格，且身份唯一、generation 正确；`Read` 返回该候选状态，不能给旧世界状态。液体/气体仍可出现在主网格占据中，但不形成结构边。
2. `Bodies` 必须保留待分析的原体目录，包括删空体。动态格引用必须有对应 BodyId；体局部坐标不套用主网格宽高，也不投影到世界网格。M04 不读体位姿建立连接。
3. `IsFixed` 必须反映候选材料实例：Remove、不同材料 Replace、同 ID Replace 都撤销原标记；单纯状态写入保留。新格没有固定标记；动态体和非结构格不得返回 true。分析器不把 `changedCells` 当失效集，因为其中也可能只有状态变化。
4. 固定标记与实例映射由 M02 统一管理；本轮真实同 ID Replace 测试使用既有 `TickInstanceMap`，没有永久实例字段或新的固定身份表。公开 `IsFixed` 没有原标记/失效句柄参数，因此 M04 无法从坐标验证提供者是否错误保留旧固定点，需候选构造测试保证。
5. 触发条件覆盖初始化、结构格 Spawn/Remove/Replace、燃尽；异连接组 Replace 即使格数不变也必须分析。一次批次须在全部裁决后的候选状态上分析，不能逐格发布。
6. 任一分析失败没有可用 Plan。外部命令由 M02 整条拒绝；规则批次准备失败由 M02 Faulted，不发布新 Tick。不要将 `NotReady` 的空体计划省略后继续提交。

目前 `WorkingWorld.OccupiedCells` 在关闭/故障租约时抛 `InvalidOperationException`，接口没有带错误码的枚举入口。分析器将这类租约异常转为 `NotReady` 诊断；`Read` 返回的具体错误码（例如 Faulted）则保留。M02 正式调度必须在已检查生命周期、所属线程及有效阶段租约后调用，不用此异常映射代替世界故障门禁。

## M05 消费、预算与所有权

- 非空计划每个结构格恰出现一次；成员和分量使用原归属坐标。`OriginalMinimum` 是分量内最小 y/x；主网格先，再原 BodyId，最后最小 y/x。connectionGroup 以 `StringComparison.Ordinal` 比较。
- 当前合同下：Grid+IsFixed 保留；Grid+非固定全部提取并新建非零 ID；同旧 BodyId 单分量保留，多分量撤销旧体并新建全部子体。这是消费说明，仍须 I02 冻结为公共字段；空体按 I01 补齐后交付。
- 成员是既有 `CellKey`。M05 在同一候选租约内用 `world.Read(member)` 获取完整原状态，用同一个 `ITickInstanceMap` 查询材料实例；不得重新初始化 Fuel/Burning 等字段。归属迁移必须落实 M02-I02，并保留湿句柄。
- M04 不限制输出分量数为 `MaxDynamicBodies`。四臂夹具容量3仍完整返回四分量；M02/M05 必须计算保留体+新体、所有形状、材料、整 Tick 变更总账及 CPU 峰值，然后整条预检。M04 不预留任何 BodyId。
- 搜索数组只在构造时分配，每次复用；公共 `StructureComponent`/`StructurePlan` 按 M00 的复制合同分配托管列表。输出归调用方持有，下一次 Plan 不修改旧计划；输入视图由 M02 持有，输出键不延长候选状态/实例租约。
- 计划成功后及任何失败后均清除内部材料组和分量引用；没有 NativeArray、物理或显示资源需要移交。释放调用方计划引用与分析器即可由 GC 回收托管存储。结构准备分配允许，但必须单列预算/峰值；此实现不声称稳态完整 Step GC=0。
- 建议合并预算时将构造缓冲及每次计划复制计入 M02-I05；全量排序/邻接二分查找为 O(N log N)，显式队列空间为 O(N)。65536格测试是正确性证据，不是 P2/P3/P4 或256MiB全系统证明。
