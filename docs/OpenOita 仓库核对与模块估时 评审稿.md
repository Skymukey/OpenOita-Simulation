## 本轮范围

首版交付可在 Unity 编辑器中绘制场景的材料世界组件，并在同一场景完成：**材料改变 → 连接与固定检查 → 全部失固部分自动提取／已有物体再拆分 → 物理运动。**

- 输入是材料布局和固定约束，不要求预先登记木板或可脱落对象；笔画也不决定物体边界。
- 外部只提交材料作用；自动识别、脱落、拆分由内核负责。运动中的材料体仍可破坏。
- 保留逐像素材料内核及 Unity 2D 适配；新增内部结构系统。对象层 ECS 可选，不是物理前置条件。
- 组件包含材料选择、Scene 画笔与擦除、固定点／区域标记、预览、保存重开及运行副本；试玩破坏不污染初始布局。
- 可以缩小探针场景，先做直接破坏；材料子集、网格演示或预置木板释放不能单独作为首版验收。
- 不包含弯曲、应力传播和承载断裂。复杂流体耦合、角色推挤、运行时绘制和高级笔刷另列范围；基础水、蒸汽行为及已确认的燃烧规则、执行状态与附着火焰效果均计入当前基线，不能整体默认推后。

原“网格 V0 先交、受限动态体 R 后交”的口径已撤回。旧 8–13 人日和 4–7 人日仅是历史范围基线，不能继续报价，也不与下表叠加。

### 首版材料

### 材料规则

- **燃烧规则已确认**：可点燃、传播、烧损，遇水熄灭，燃尽消失；无烟、灰和耗氧。
- 燃烧状态随承载材料保存；默认燃料为 250 个燃烧 Tick，每 10 个燃烧 Tick 向四邻接传播，新点燃格下 Tick 开始更新。水四面接触先灭火，水不消耗、不蒸发；熄灭保留剩余燃料，之后可再点燃。燃尽前保留整格质量与碰撞，燃尽删格才更新结构与几何。
- 水默认每2 Tick先尝试净向下原子液体链，再下／斜下／有效横移，每实例最多一邻格；2026年10月5日新增[M03-L01液体平衡补充](specs/M03-L01-液体扩散与液面平衡.md)，要求摊平、平台溢流及防往返，算法、实现和验收待完成，本文旧估时不代表已覆盖该项。蒸汽仍每3 Tick按上／斜上／横向尝试单格移动，200 Tick自然消散。普通移动只入原空格，原子水链可进入同链下一源但末端须原空且更低；边界阻挡，不穿角、不交换水汽。蒸发、冷凝等额外反应不纳入当前基线。

上述具体数值与技术选择是可调的实现默认值，不等于用户逐项确认。步长默认 0.02 秒、格长默认 0.1，完整字段、规则阶段及冲突裁决见[实现方案](<D:/work/Project/OpenOita/docs/OpenOita 初步实现方案 草案.md>)，无需等待策划逐项决定接口字段或算法。

### 配置与结构基线

材料统一由一个 `materials.json` 加载，采用 `schemaVersion=1`、`materialSetId`；`kind` 只分类，`tags` 显式选择内置规则。标签在加载时转为 `RuleId` 和 `ulong` 位掩码，参数共享，格子只保存材料 ID 和实例状态；未知键、标签和非法范围拒绝整个配置。样例与 Schema 已纳入本轮文档交付，运行时加载器、规则注册和绑定仍需编码及验证。

结构按四邻接且同 `connectionGroup` 连接；混凝土与木头均属 `building`。固定约束附着材料格，删格删锚；碰撞不焊接。`MinRigidBodyCells=1`，全部分量含单格碎片保留刚体；采用贪心矩形精确覆盖生成碰撞，不转散粒。默认 256×256 世界、128 格区块，材料合计上限 65536 格、动态体 64 个、每体矩形 256 个、静态与动态材料总形状 4096 个，世界边界另设 4 个碰撞形状并单独计入预算；每 Tick 材料变更 65536 项。外部命令超限整拒绝，自动规则失败停步并报告，不能丢料。

独立 Unity 2D 物理最多 8 子步；运动体覆盖水汽时整批暂存，最早下一Tick尝试原格/附近恢复；无合法落位继续等待且Ready，资源故障仍按合同处理。材料总量含暂存，蒸汽寿命继续每Tick扣减；F01尚未实现，本稿历史估时不表示已覆盖新增工作。编辑器采用自定义 Scene 画笔，初态保存 `cells`、`fixedCells`、`initialBurning` 与材料集标识，不保存运行 `BodyId`。

### 显示要求

火焰是燃烧规则执行时的附着视觉效果，不是材料，不单独占据材料格。效果随承载材料移动、旋转和拆分，熄灭或燃尽后清理；不提供烟、灰的视觉效果。

| 静态固定、接触支撑和结构连接混淆 | 明确锚定与连接规则；还有固定连接时不得误脱落，接触不得自动粘合 |
| 大量碎块、薄连接和孔洞导致重建峰值 | 记录连通访问量、贪心矩形数量及重建耗时；测集中破坏及多体持续运动，不只测稳定帧 |
| 小分量无法稳定表示或容量超限 | 探针先验证；保留可核对材料，明确失败／暂停结果，不静默丢弃 |
| 旋转映射、速度继承或质量更新错误 | 校验世界与局部坐标、质心、惯量及新体速度；拆分不凭空改变材料数量 |
| 编辑布局被试玩覆盖 | 保存资产与运行状态分离；重开、重置及退出运行后核对初始布局 |
| 运行加载、资源残留与依赖漂移 | 早期打包；验证失败清理和重复生命周期，记录实际解析依赖 |
| 支援、发布最低配置和游戏接入方未落实 | 开发机先作工程基线并记录型号；只按实际认领产能排期，缺接入或测量证据不能标记整体通过 |

T9分项记录：

- **材料**：水、混凝土、蒸汽、木头的配置与加载。
- **规则**：按默认周期验证水／蒸汽移动和蒸汽消散；逐项覆盖已确认燃烧行为与排除项，验证新点燃下步更新、水接触优先灭火、熄灭保留剩余燃料与再次点燃；燃尽前保持整格质量／碰撞，燃尽更新结构并清理状态。
- **显示**：附着火焰随材料移动、旋转和拆分，熄灭或燃尽后清理；无烟、灰效果。

性能首先以开发机作工程基线，发布最低配置另定。固定负载的拟定目标为：稳定完整 Step 的 p95≤10 ms、p99≤16 ms，集中破坏 Step 峰值≤50 ms，稳定 Step 的 GC Alloc=0，模拟专属 CPU 内存峰值≤256 MiB。当前没有实测结果，这些数字是验收预算，不能当成性能保证。

性能记录须包含真实开发机 CPU／GPU 型号、包版本、后端、场景格数、活跃材料、体数与碎片数、Step 分位耗时、最大重建耗时、分配及峰值内存。启动解析、运行表与标签判断、邻域规则、结构和几何分别记录；不虚填机器信息，也不在测完后倒推通过标准。

交付证据包括源码与依赖、组件及场景资产、PC 包、配置样例、中文操作与接口说明、真实接入示例、测试结果及已知限制。完成代码或演示一次均不等于验收通过。
