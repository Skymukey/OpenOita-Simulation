## 目标与边界

建立唯一权威状态、只读已提交视图和统一事务协调器，负责Create/Step/Reset/Dispose、模块装配及Host驱动。本模块的agent是集成负责人，独占WorldSimulation和WorldHost。不在此复制规则、连通、精确几何或渲染算法；这些通过冻结接口接入。

## 阶段A：状态与准备协议

1. 实现C02全部字段及材料创建/Replace/Remove初始化。主网格可写接口仅内部使用；所有读取均区分合法空与越界，合法缺块不得分配。
2. 固定点绑定材料实例，Remove/Replace同步撤销。动态体状态由M05管理，M02统计主网格＋全部体＋暂存的全世界材料、命令、形状及工作缓冲预算，并唯一持有暂存记录/候选/提交副本。
3. 保留不可变编辑初态副本。工作状态与公开快照分离；需要复制的CellState、运行表、体位姿和派生版本都有容量、释放和内存计量。
4. 建立D01实例迁移表及D02跨整Tick变更集合，提供共享操作入口。MaterialIds只作为显示缓存，不成为第二事实源。
5. 实现prepare/validate/apply/abort协调：单命令或一个已裁决规则批次的材料、全部体、几何、质量、占据与显示关联必须共同预检。准备失败释放全部候选资源，不能边找分量边不可逆创建。
6. 只有受控测试夹具可注入失败；正式路径没有“无物理也报告Ready”的桩实现。

## 阶段B：生命周期与统一Step

1. Create调用M01，创建临时世界；M04检查初态全部分量、M05提取自由体、M06准备物理/边界、M07B准备显示后才发布generation/Tick0及Ready。容量不足整次失败并释放资源。
2. Step仅Ready、所属主线程、无重入时执行；步长来自创建配置。按C04九阶段调用M07A、M03、M04/M05、M06，不能以按组件Update顺序代替调度。
3. 每条命令独立预检；可预知外部输入失败只拒绝本条。规则/求解故障或无法保障内部一致性时进入Faulted，不增加committedTick、不发成功事件、不展示候选位姿。
4. 只有完整成功后发布世界查询视图、命令结果、ChangeSet与版本，再通知订阅者。通知允许查询/入队；入队命令下一步执行；通知中的Step/Reset/Dispose返回Busy。订阅者异常单独记录，不中止其余订阅者的通知或撤销提交。
5. Reset使用创建初态重建，generation增加、Tick=0，清旧令牌、全部暂存记录和引用，新Tick0暂存为空；失败进入Faulted，不恢复旧可运行世界。最后成功的显示快照保留至新Ready发布或Dispose，不展示半新世界。Tick/generation/ID/序号推进都做溢出检查，不循环复用。
6. Dispose可重复，释放世界及所有模块资源，之后其他操作返回Disposed。故障阶段的配置/诊断仍可查询，普通材料接口返回Faulted。
7. Host自动/手动互斥；自动用本世界固定步长累计时间并调用Step，不更改Time.fixedDeltaTime或默认Physics2D场景。帧落后可保留时间积累，不能悄悄改变h或多驱动一次。关闭/重开与失败创建走同一资源拥有者路径。
8. Host提供显式三文件来源、origin及自动/手动选择，验证旋转0/缩放1；接入M08试玩副本和Reset。首版不做运行中更换origin或热加载。

## 上下游交付

向所有计算模块提供只读工作阶段视图和受控意图/准备入口；向M07A提供只读已提交视图、版本及队列执行回调；向M07B提供CommittedRenderView和ChangeSet。M02持有并发布版本，其他模块不能各自推进committedTick。

ChangeSet区分生成、显式移除、燃尽、自然消散、状态变化、进入暂存、恢复到网格、所有权转移、体创建/撤销和旧新BodyId映射；转移不计消耗。每材料守恒台账覆盖主网格、全部体与暂存；暂存/恢复不作消费。物理位姿、暂存/恢复、实例映射、整Tick计数和快照必须联合采用；无恢复目标保持Ready，实际资源/内部故障仍冻结。九阶段时序、寿命和恢复点按F01执行。
