## 1. 目标与非目标

目标：提供 Unity Scene 自定义材料编辑工具，使用户可以选择材料、绘制、擦除、设置固定与初燃标记、预览、保存和加载编辑初态，并能用同一创建流程试玩。保存重开不改变初态；试玩与 Reset 不污染编辑数据。

非目标：运行时画笔、撤销重做、纹理/自定义笔刷、Tilemap 存储、运行中存档、热加载、自动迁移旧材料 ID、物理参数编辑器或公开测试速度接口。不能用运行时世界快照代替编辑初态，也不能为绕过提取实现要求而预登记将脱落的碎块。

## 4. 必须实现的行为

### 4.1 编辑模型和文件格式

1. `SceneMaterialData` 表达可编辑初态，包含版本/材料集合/文件引用、非空格及固定/初燃坐标，不包含水汽暂存记录、恢复锚点/身份、BodyId、动态变换、燃料余量、气体寿命、运行速度或中途 Tick。
2. 格数据以坐标唯一；保存 `materialId`，不保存材料对象或规则对象。ID 0 表示空，不输出到 `cells`；材料选择显示 M01 已验证的材料，不写死四个按钮或按旧材料名称推断 ID。
3. 导出严格遵守 [scene.schema.json](../schemas/scene.schema.json)：`schemaVersion=1`，材料集合与材料文件一致，`materialsFile="materials.json"`、`worldConfig="world_config.json"`，两个引用都只允许同目录固定文件名。
4. `cells`、`fixedCells`、`initialBurning` 各自按 y、x 升序输出且无重复坐标；坐标必须落在配置 width/height 的左闭右开范围内。固定标记对应 structure 格，初燃标记对应 burnable 格。
5. 擦除或替换材料时撤销旧材料实例的固定标记；新材料不会继承旧锚点。初燃标记不得悬空或错误附着到不支持燃烧的材料；编辑模型对删除/替换清除旧标记，重新设置由标记工具显式完成。画笔覆盖已有格按替换处理，即使材料 ID 相同也作为新实例，不因同 ID 绕过标记清理；新空位绘制按新增处理。
6. 不补缺失字段、忽略未知键、猜测材料集合映射或转换旧石头/沙 ID。无效导入返回具体文件、字段、错误码与中文说明，不提交半份模型。

### 4.2 Scene 工具与坐标

1. 提供材料选择、1–128格圆形/方形连续画笔、矩形工具、擦除、固定标记、初始燃烧标记、网格预览、创建、保存和加载。大小1保持单格语义；连续拖动补齐采样间路径，矩形松手一次提交。标记工具允许设置与取消，选择无效材料时给出明确诊断。
2. 编辑直接作用于 SceneMaterialData，不依赖 Tilemap；初态预览不驱动物理或规则，能区分材料、固定标记和初燃标记。
3. X 向右、Y 向上；格中心为 `origin + cellSize × (x+0.5,y+0.5)`，点转格使用向下取整，左/下边界包含，右/上边界排除，空位与越界分开报告。
4. Host 必须零旋转、单位缩放，运行中 origin 不变。编辑 UI 校验这些前提并明确提示，不静默修正 Host 变换。
5. 矩形选格采用实际格中心是否位于左闭右开世界矩形的标准；光标/擦除预览和实际编辑使用同一选格函数。对动态体的只读试玩选区若提供预览，复用 M07A 的实际材料选择，不能按 AABB 填满旋转体孔洞；首版不借此增加运行时画笔。
6. 无固定连接的初态结构在进入运行流程时由结构模块自动提取；编辑工具可以显示固定标记，但不得自行创建“将脱落物体清单”或偷偷添加固定点。
7. 按[公共合同C01](CONTRACTS.md#c01-数据与坐标)，单格工具即单逻辑像素工具；在1:1及整数倍放大下始终只命中一个逻辑坐标，不能把一次单像素操作扩成2×2或8×8。矩形工具明确显示逻辑像素宽高，预览范围与实际修改一致。
8. 标准材料预览默认1:1并显示逻辑尺寸与倍率，复用M07B精确像素视图；网格线默认关闭、可作为调试层单独开启。Scene自由视角不等于1:1，应能进入标准1:1预览；切换倍率不修改编辑初态、固定／初燃标记或保存内容。

### 4.3 加载、保存与失败保护

1. 由用户明确选择配置目录或 scene.json 后，读取同目录的固定三文件，交 M01 同一严格解析/校验流程。编辑器不扫描整个 Assets 材料目录。
2. 加载先构建临时模型并完成跨文件校验，成功后一次替换当前编辑模型；失败保留当前编辑内容和原文件，诊断可定位问题。
3. 保存前完整校验编辑模型及文件引用。使用统一 DTO/序列化规则生成文本，先完整写入目标同目录的临时文件，再按冻结的文件替换协议替换目标；首次保存也必须在临时写入完成后才发布目标。
4. 临时写入、关闭/刷新或替换任一步失败，都不能先截断目标或把部分文件当成功。保留原目标内容并报告实际失败阶段，不回退为直接覆盖。
5. 临时文件必须有本次操作的明确拥有路径。失败可保留并在诊断中给出路径；若清理，只能逐次删除明确拥有的单个文件，不扫描或批量删除目录。不得清理用户其他文件。
6. 普通保存只更新编辑初态文件，不改写 materials.json 或 world_config.json 的参数；引用文件缺失或不匹配时通过诊断引导修正。用户显式创建空白场景或另存时，可以从已校验模板生成新配置；只向不存在的新目录写入完整三文件，scene最后发布，不覆盖现有引用文件，不承诺三文件跨文件事务。

### 4.4 试玩、Reset 和生命周期

1. 进入试玩对编辑初态建立独立副本，使用与 Windows 启动相同的 Create 输入流程。运行中的材料写入、燃烧、提取、运动均不得回写 SceneMaterialData。
2. 退出试玩关闭世界并释放其资源，恢复编辑视图；保存始终保存编辑模型。试玩期间可以禁用编辑操作，但要在界面明确当前模式，不能保存运行状态冒充初态。
3. Reset 使用 Create 时保留的初态副本，generation 增加、Tick 回到 0，旧暂存全部清理，新初态暂存为空；初燃从满燃料且 IgnitedTick=0 开始。此过程由 M02 实施，Editor 只发请求并显示结果。
4. Editor 不直接改固定步长、宿主全局重力/物理模式或默认场景。自动/手动驱动互斥；提交通知内不直接调用 Step/Reset/Dispose，Busy 与故障诊断按公共合同交 Host 延后处理。
5. Editor API 留在 Editor 程序集中，Windows Player 不引用 UnityEditor；选择变化、工具关闭、退出试玩及初始化失败都要释放 Editor 自己拥有的预览和订阅。
6. 编辑与正式试玩使用同一已校验width/height/cellSize；不得为适应窗口或复用演示而硬编码成256×256、0.1或扩展布局。独立模块探针自有配置须明确标示，不作为配置预览或正式试玩的替代。

F01试玩诊断按同一成功版本区分活动材料、暂存水/蒸汽和总量，等待不显示为故障或材料丢失；退出试玩释放全部暂存记录及缓冲。F01-09核对保存仍是编辑初态、Reset及20轮退出清理，不新增运行存档。
