## 1. 目标与非目标

目标：把主网格、动态材料体及燃烧状态的**已提交版本**显示出来，使材料颜色、空洞、位姿、逐格烧损和附着火焰与同版本查询一致；正确处理拆分、撤销、Reset、Faulted 与资源释放。

非目标：计算燃烧规则、物理推进、连通拆分、命令或查询裁决；不加入烟、灰、耗氧、第五种火材料、逐格 GameObject、动态体位姿插值或运行时画笔；显示不修改材料、质量或碰撞。不得把只支持预置刚体或静态火焰演示当作完成。

## 4. 必须实现的行为

### 4.1 提交版本与帧末同步

1. 显示输入只来自成功发布的 `generation + committedTick`。工作 Tick 的中间材料、物理候选位姿或失败事务不得进入可见显示。
2. 事件视图仅在回调内有效。需要帧末使用的数据必须复制到显示拥有的缓存或取得 M00 明确批准的稳定只读快照；不得保存即将失效的 ChangeSet/临时数组引用。
3. 同一帧多次成功 Step 合并脏范围，帧末上传最终成功版本。合并必须包括材料 ID、燃料/Burning 等纯状态变化、体创建/撤销、归属转移、几何变化和位姿变化，不能只依赖旧 `WorldChunk.Dirty`。
4. 发布显示逻辑版本与 GPU 上传版本供诊断。帧末检查上传完成的 generation/committedTick 与本帧选定提交版本一致；主合同不要求任意查询瞬间 GPU 已同步。
5. Faulted 后保留最后成功提交的材料与位姿显示，禁止使用失败 Tick 数据。Reset 成功后整体转到新 generation 的 Tick 0，旧体、旧火焰和旧缓存引用均失效；Reset 失败进入 Faulted 时不发布新初态或半成品。Dispose 释放显示资源，可重复调用。

### 4.2 主网格与动态体显示

1. 主网格按 `origin + cellSize × 格坐标` 放置；格正方形边界与中心采用主合同坐标函数。区块边长为 `128 × cellSize`，逻辑尺寸外尾格始终透明。
2. ID 0 透明；其余颜色来自共享材料定义，合法稀疏 ID（包括 65535）能显示。不能将未知 ID 的诊断色替代加载阶段的合法性校验。
3. 成功进入暂存的水汽不渲染，原纹素清空，恢复时按同一成功版本显示目标纹素；隐藏记录本身无火焰。空区块、已撤销体、最后一格被移除、材料从主网格提取到体后，原显示位置必须清空，不能因“当前为空”直接跳过旧纹理或旧对象清理。
4. 动态体按局部格和几何原点生成显示，应用已提交的连续平移/旋转；不得以质心替换几何原点，也不得把旋转后的采样结果写回主网格。首版不做位姿插值。
5. 单格碎片必须可见，3×3 环形材料的中心孔保持透明。拆分后所有子体显示保持格世界位置，与实际 BodyId 映射一致；原 BodyId 保留但质心变化时也不能发生显示跳动。
6. 烧损显示从 `FuelTicksRemaining / fuelTicks` 派生，燃料降低时显示变暗并在熄灭后保留烧损程度；具体色调作为可调显示参数记录，不能反向改变状态。余量大于 0 时仍显示完整材料格，燃尽时才清空。

### 4.3 附着火焰

1. 仅对已提交 `Burning` 格生成火焰；按每个区块或动态体构建批量四边形，使用独立火焰材质和统一动画时间，不逐格生成 GameObject。
2. 火焰不分配材料 ID、不占格、不增加质量或碰撞；无烟和灰效果，不以视觉动画决定传播和燃尽。
3. 火焰与材料使用同一版本和局部坐标变换，跟随提取、平移、旋转与再次拆分。拆分后旧 BodyId 的火焰关联清除，仍燃烧的局部格归属到正确的新体。
4. 熄灭、燃尽、Remove、Replace、Reset 和 Dispose 清理对应火焰；纯状态变化也须触发刷新。重复 Ignite 不能由显示端重置燃料或传播周期。
5. 统一动画时间只是外观输入；暂停/Faulted 时动画时间的表现可以固定或继续，需记录选择，但火焰集合、材料状态和位姿必须停留在最后成功版本。

### 4.4 资源和开销

纹理、GraphicsBuffer、Material、Mesh、火焰批次、显示对象、上传缓存与事件订阅都要明确拥有者。初始化中途失败按拥有者释放已创建资源；Unity 对象即使延迟销毁，也须立即停用旧可见显示与订阅，避免下一帧残影。共享 Mesh 不得重复释放，也不能无界遗留。

复用稳态上传与火焰工作缓存，资源增长受世界已验证容量限制；结构重建产生的分配单列记录。不把 1920×1080 的渲染帧耗时混入纯 Step 开销，也不因显示测试通过宣称 P2/P3 的模拟目标已通过。

### 4.5 逻辑像素与屏幕显示（公共合同1.5补充）

1. 遵守[公共合同C01](CONTRACTS.md#c01-数据与坐标)及[主方案5.3](<../OpenOita 初步实现方案 草案.md#53-像素粒度与显示约定>)：每个逻辑像素对应一份独立状态及一个原始材料纹素。主网格和体局部纹理保留逐像素颜色、孔洞及烧损，Chunk、图集、批次与碰撞矩形不能降低模拟或材料纹理分辨率。等价非纹理绘制须满足相同逐像素输入和覆盖断言。
2. 标准材料预览默认1:1，显式支持整数倍放大，显示当前逻辑尺寸及倍率。窗口不足时裁剪或平移；可选适应窗口模式标明倍率并提供1:1恢复入口。UI缩放、窗口尺寸、DPI和Game View缩放均不能改变世界配置或独立状态数。
3. 在精确像素视图采用Point采样、对齐最终画面像素边界，避免mipmap、插值和后处理重采样混色。默认完整填色，不缩小每格矩形制造黑线；网格线是默认关闭的独立调试层，关闭后不得残留缝隙。验收关闭火焰、标记及几何框等叠加，按未二次缩放的游戏输出像素读回并记录尺寸。
4. 1:1及k×k屏幕覆盖断言只对轴对齐、边界对齐的主网格成立。动态体仍使用已提交连续位姿，旋转后验证局部像素身份、空洞及查询一致；显示端不得吸附物理坐标、量化体位姿或回写旋转采样。
5. 配置预览与正式试玩读取已校验width/height/cellSize；独立模块探针可以使用明确标示的自有配置。模板8×8展开是生成64份状态，不能作为纹理放大实现。Render消费实际快照尺寸，M02负责输入接线，M08负责视图入口；模块预览的独立控制器由集成负责人整改。

2026年10月5日`Preview/M05PreviewController.cs`已完成独立探针整改：Point纹理、默认1:1、显式1/2/3倍、整数平移/裁剪、默认关闭网格及几何框；界面明确自有256×256和cellSize=0.1配置。Editor已读回1倍及3倍实际输出，见[整改记录](../validation/像素粒度-整改与验证.md)。这不替代正式渲染器、同配置编辑/试玩、旋转查询及Player的08–11完整验收；M07B只交付渲染能力与接线需求，不因此扩大第3节代码修改归属。

F01-08另验无恢复目标时世界仍Ready、成功隐藏与后续恢复的1倍/3倍实际GPU输出。该分支不冻结旧画面；仅真正故障继续保留最后成功版本。暂存蒸汽寿命等隐藏状态不生成可见像素，但数量诊断仍须同版本。

## 6. 具体工作步骤与检查项

1. 对照 M00 核对输入字段和引用有效期；列出 Host 接线与 Body 数据缺口，冻结后再编码。
2. 为旧 Render 逐项建立资源所有权表，替换 ID 直接切片和每次上传数组分配，先通过静态颜色、空格、尾块、坐标测试。
3. 实现提交缓存、版本记录、脏范围合并与空内容清理，使用故障夹具证明不读工作状态。
4. 实现动态体局部显示和 body 生命周期；覆盖提取、单格、孔洞、旋转、保留 BodyId 的质心变化、全部子体拆分。
5. 实现完整格烧损显示和批量火焰；将状态清理接入全部生命周期路径。
6. 由集成负责人接线，运行真实 M05/M06/M07A 流程；分别记录功能、资源和渲染开销。
