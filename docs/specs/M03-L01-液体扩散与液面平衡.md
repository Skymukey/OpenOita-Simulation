# M03-L01：液体扩散与液面平衡

日期：2026年10月5日｜状态：原子液体链已实现，Unity Editor新增规则37项、M02核心19项及实际预览已通过；[实际证据与边界](../validation/M03-L01-液体平衡实现与验证.md)。正式World/Player与性能仍待验。归属M03，接线归M02，夹具与集成验收由M00/M09配合。

本补充针对M05Preview中水落到平台后长期堆高、横向扩散不足的问题。它补齐[主方案4.2](<../OpenOita 初步实现方案 草案.md#42-水与蒸汽移动>)、[M03](M03-材料规则与燃烧.md)和[公共合同D04](CONTRACTS.md#c10-本次拆分补充的技术默认)；旧M03-A测试结果仍是旧规则的历史证据，不能覆盖本补充。

## 1. 必须达到的行为

- 水通过净向下的原子液体链及单格下落/扩散运动；落到平台后，有通向低处的开放路径时，应持续向平台边缘扩散并落下，不能长期堆成砂堆。
- 在静态、开放、平底水槽中停止注水后，水必须在固定验收期限内形成无悬空孔洞的水层。各列水深相差至多一格，允许离散格造成的一格台阶。
- 横向移动必须服务于扩散和降低堆积；不能仅因当前位置或Tick奇偶变化，在相邻位置反复往返而始终不向低处推进。已达到平衡且环境不变时，应停止材料搬运。
- 有效通道跨越区块或长于局部搜索范围时仍须最终传播流动，不能把“附近没找到落点”当作整个水体已经平衡。
- 墙、封闭墙角、世界边界、其他材料和真实固体占据仍然阻挡水。隔墙两侧不能仅因液面高度不同而交换水量。

范围是主网格中的离散液体扩散。首版仍无压力求解、浮力、惯性波浪、表面张力或水对刚体的反作用力；不要求封闭连通器经水下通道向上顶升水面，也不要求水自行越过高于水面的挡板。M06的刚体排水不能代替日常流动，M07B的显示也不能修改材料来伪造摊平。

## 2. 移动、方向与提交约定

### 保留的约束与原子链例外（公共合同1.7）

1. `moveIntervalTicks=2`仍表示每两Tick尝试一次，初态倒计时0对应Tick 1、3、5；成功或受阻都重置倒计时。计时依赖固定Tick，不依赖帧率或显示倍率。
2. 每个水实例每个阶段至多移动一次，实际步长仍是相邻下、斜下或水平一格。不向上、不瞬移；长路径由多个实例同时各走一步形成，不能把链首直接传送到链尾。
3. 普通移动目标必须在水阶段开始时为空；斜移侧格必须可通行。**唯一占据目标例外是同一已预检原子液体链的下一源格**，且下一实例必定在本批离开。其他同阶段新空位不能作为普通候选，蒸汽和其他材料没有此例外。
4. 链只包含同MaterialId、带LiquidFlow的主网格水，沿下/左/右正交相邻格，不含上移或对角边。链尾在阶段快照为空，且低于链首；不能穿固体、异材、蒸汽、真实固体占据或封闭墙角。禁止闭环、纯水平整体滑移、分叉、未释放占据目标以及只提交链的一段。
5. 每源至多一个成功移动，每目标至多一个来源，链之间不能共用节点。完整CellState、材料实例和湿标记随各自一步搬运；水量逐Tick守恒，跨块和块内等价。
6. 整批统一预检。源同时是另一移动的目标时，最终材料写入是前驱实例的状态，不能被清源覆盖；候选实例按尾到头迁移，所有中间位置即使状态字节相同也因实例变更计入D02。容量不足或任一链不合法时整批失败，不发布半批或丢水。

旧“全部目标必须原空”的约定使厚水体只能从表皮缓慢扩散；独立探针中多个方向方案未在期限内摊平。因此本次明确增加原子链例外，保留相邻单步、守恒、障碍及原失败边界，不通过增加每实例步长或放宽验收期限解决。蒸汽原五层规则不变。

### 确定的选择与搜索顺序

1. 先计算水的倒计时及可移动集合，再按源`y`降序、`x`升序选择上方为空且不被真实固体遮挡的自由表面水格。已被此前链使用的源跳过。
2. 从该源作广度优先搜索：只穿过本阶段可移动、未预留的同材水节点；邻接顺序为下、首选水平、次选水平，左右首选沿用该链首的D04种子奇偶。每节点至多入队一次，最多访问当前材料缓冲容量N个节点，不使用固定局部半径。
3. 收集低于链首的可达原空终点，优先最低`y`；同高度取最短路径，等距保持上述稳定BFS发现顺序。记录父节点还原完整路径，先预留全部节点，再输出每条相邻边的Move意图。链净高度变化严格为`尾y-首y<0`，不产生水位不降的闭环搬运。
4. 未参与链的水继续按下、首选斜下、次选斜下三层尝试原空目标；水斜下与蒸汽的旧奇偶预期保留。不得占用任何链节点或末端。
5. 最后处理有效横向扩散：沿源所在行的连续空通道寻找低于源的空位，只发出朝该方向的一格横移；对两侧按可达下降位置与路径距离排序，完全等价时才用种子奇偶。有效方向不能仅因下一步位置奇偶而反转。无低处依据的孤水或已平衡水层保持原位。

普通同层候选仍按目标`y/x`、源`y/x`裁决；无合法后备则保留原位。全部决策来自阶段快照和本阶段预留，不能依赖字典、区块遍历顺序或系统时间。候选/父节点/队列/访问标记复用有界缓冲，不增加CellState字段、公开DTO或跨Tick缓存；Replace/Remove/Reset后从新快照重建。

### 算法与实现验收边界

独立探针已在seed=1/2验证F1–F4及拆墙，并额外观察128 Tick零搬运；这是方案选择依据。最终C#规则、M02提交和预览结果已由Unity测试确认，实际收敛Tick及缓冲预留见[验证记录](../validation/M03-L01-液体平衡实现与验证.md)；阶段耗时、可靠GC和完整峰值内存仍待验，不能复制探针数字作为运行结果。搜索最坏工作量随自由表面源数和材料节点数增加，必须回归P2；仅有内存上限不代表性能通过。

## 3. 平衡的判定与计时

固定布局、逐格初态及计算例子见[液体平衡验收夹具](../examples/液体平衡验收夹具.md)。期限是本次新增的工程验收目标，Editor固定夹具与预览已满足；正式世界命令/Reset、Player及性能结论仍按验证记录区分。

- 平底槽的列水深`H(x)`为从槽底向上连续水格数；空列记0。所有内部列均计入，不能只统计已有水的列。水层下方不得有空洞或残留悬空水格。
- 平底槽平衡要求`max(H)-min(H) <= 1`且水量不变。带平台的夹具按“较低可用空格先填满”的明确终态验收，不能把平台高度差当作水深误差。
- 首次满足几何条件后，继续128 Tick：所有水格占据位置保持不变，水阶段成功搬运数为0。倒计时正常变化不算搬运，不要求CellState字节哈希静止。
- 期限从初态Tick 0或指定地形变化提交后开始，包含下落与摊平；128 Tick稳定观察额外计算。1倍夹具期限256 Tick，8倍夹具期限1024 Tick。间隔均为2；其他间隔另立用例，不能沿用这些期限宣称通过。
- 记录首次满足条件的Tick、每Tick水量/成功搬运数、最大水深差、孔洞数和占据哈希。重复形状用于定位周期振荡，不能仅凭两个相邻Tick不动判定平衡，因为移动倒计时本就会产生空闲Tick。

## 5. 交接与完成出口

M03负责方向搜索、候选裁决、纯规则夹具及算法记录；M00提供复用夹具和必要公共类型；M02负责辅助状态生命周期、整批搬运、实例/湿集合和预算；M09把新增用例加入T6及相关T7/T9，并在Editor和Windows Player分别留证。M06仅提供实际固体占据与接触输入，不承接液面平衡算法。

搜索缓冲必须有确定上限并复用；记录新增阶段耗时和峰值内存，回归主方案P2的完整Step耗时、GC与内存目标。不能以1024 Tick收敛代替性能验收，也不能以纯规则通过代替实际世界集成。

本补充不新增材料标签或JSON参数，不改`schemaVersion=1`、`materialSetId=openoita-core-v1`、默认世界尺寸或`moveIntervalTicks=2`。Schema只同步字段语义说明；夹具坐标是测试配方，不是新场景格式。搜索半径不借用M06的`fluidDisplacementRadius`。
