# M06-F01：水汽暂存与恢复

版本：1.1（接口冻结及实现接线）｜日期：2026年10月6日｜对应公共合同1.10、主方案0.10｜状态：正式World已接线，Editor功能验证通过；Player与性能实际完成边界见[实现记录](../validation/M06-F01-实现与验证.md)。

本补充替代原M06的“每子步立即排开全部水汽，无合法目标则Faulted”条款。已确认的方向是：固体覆盖的水汽暂时离开活动网格和画面，完整状态保存在有界的待恢复集合；之后尝试恢复，没有空位就继续等待。历史M06/M07/M08测试及Player失败记录保留原结论，不能作为本补充的通过证据。

## 1. 范围与权威状态

首版只处理主网格中的水、蒸汽被运动固体覆盖的情况。水汽不产生压力、浮力或刚体反作用；不增加自由飞行粒子、速度积分、飞溅、蒸发或冷凝。固体的局部网格、连续位姿、结构提取和碰撞几何保持原设计。

每份非空材料在一个工作或提交版本中，只能属于主网格、一个材料体或一条暂存记录。暂存不是删除，也不是另存一份仍然活动的材料。对每种材料分别核对：

```text
材料总量 = 主网格数量 + 全部材料体数量 + 暂存数量
本步总量 = 上步总量 + 显式生成 - 显式移除 - 燃尽 - 自然消散
```

暂存与恢复是归属转移，不计生成或消耗。`maxMaterialCells`约束上述三部分合计；暂存记录数量自然受此上限约束，不新增配置字段。候选副本只计内存，不重复计材料总量。

M02唯一持有暂存权威集合。每条记录至少保存所属generation、稳定非零记录ID、完整`CellState`、原主网格坐标和进入暂存的workingTick。记录ID在同generation内不复用，不能用原坐标代替身份；不同记录允许具有相同原坐标。原坐标是恢复锚点，不随刚体移动，不构成占据或材料接触。暂存记录ID与BodyId分属不同身份域；既有Tick内实例句柄不升级为永久句柄。

接口已在本轮按第8节统一冻结，M02/M03/M06等消费同一合同；实现与当前验收状态见[M06-F01实现记录](../validation/M06-F01-实现与验证.md)。

## 2. 物理子步中的整批暂存

1. 每个子步读回全部候选位姿，按原M06标准检查有限运动、速度、位移、边界与固体间微穿透。水汽不能用于放宽这些检查。
2. 用真实固体格正方形与活动主网格水汽格的正面积重叠收集全部冲突源，按源y/x排序并去重。几何共边、纯相切不构成覆盖；不以AABB重叠替代精确判定。
3. 暂存前记录有效水接触，并沿用M03灭火操作。已发生的湿接触在本Tick内保留，不因水进入暂存而撤销。
4. 为整批源准备完整状态、记录身份、实例映射、源清空、暂存新增和候选位姿。统一预检材料总量、记录容量、整Tick变更数和CPU工作集，再一次采用；没有“先找到空位”的前提。
5. 暂存后源网格为空，材料只存在于暂存集合；它不参与活动占据、流动、邻域、灭火接触、普通查询或材料显示。同一源被多个固体覆盖也只能产生一条记录。
6. 新进入暂存的记录本Tick不恢复，最早下一Tick尝试。即使固体在后续子步离开，该记录也至少进入一次成功提交的隐藏状态；多个成功Tick在同一渲染帧合并时，不保证屏幕一定显示一个隐藏帧。

暂存准备或采用失败仍遵循原原子边界：不公开半批状态，不发布失败Tick；必要时Faulted。Unity求解器可能已经推进，不承诺回滚。没有恢复目标本身不属于这类故障。

## 3. Tick时序、寿命与接触

沿用九阶段调度。第3阶段只移动活动水；第4阶段对活动及暂存蒸汽各减一次寿命，到0按自然消散移除。暂存水不执行流动；暂存水汽的`MoveCountdown`暂停，恢复时保留余量。暂存中的其余状态不重新初始化。

第8阶段逐子步暂存覆盖的活动水汽；全部子步成功后、发布前执行一次恢复阶段，无动态体时也执行。只处理进入暂存Tick早于本workingTick且未消散的记录。恢复的水汽本Tick不再流动，也不再次扣蒸汽寿命；下一Tick再按普通规则处理。

因为暂存发生在第4阶段之后，当Tick新暂存的蒸汽已经扣过本步寿命；下Tick先在暂存集合中扣寿命，再决定是否恢复。到0直接自然消散，不能恢复为寿命0的蒸汽，也不能通过反复暂存刷新寿命。

暂存材料没有活动几何，不凭原坐标产生水接触。恢复后按最终工作位姿补充精确水接触，立即熄灭相关燃烧格，最迟本Tick发布时生效；不回滚此前燃烧阶段已消耗的燃料。所有湿标记仍由M02维护，规则和适配器不能建立第二份身份表。

## 4. 恢复搜索与竞争

每Tick使用最终工作世界的活动材料和固体占据快照。记录按进入暂存Tick、原y、原x、记录ID升序处理；目标先试原坐标，再按四邻接最短路径距离、目标y/x升序选取合法空格。集合的实际存储和字典枚举顺序不能改变结果。

合法目标必须在世界内、活动主网格为空、真实格正方形与最终固体无正面积重叠、且未被其他恢复记录预留。水汽不能覆盖活动材料；记录的原位置若被Spawn等命令填入材料，同样不能强行恢复。

附近搜索从原坐标出发，最短路径长度不超过`fluidDisplacementRadius`，默认16格，禁止斜穿墙角。锚点若被动态固体覆盖，允许作为搜索起点；其后每个节点均须位于最终固体占据外。锚点被静态结构覆盖时本Tick直接等待，不通过该静态格向墙外搜索。其他节点可以经过活动水汽作为连通通道，但不能以它们为目标，也不搬动中间格；不得穿过静态墙、动态固体或世界边界。此处使用最终占据，不再同时阻断子步起止两个位姿。

为可恢复记录准备唯一目标，找不到目标的记录保持原状态和身份。先完成全部选择和统一资源预检，再一次采用“移除对应暂存记录＋写入目标网格＋迁移实例”；允许恢复可放下的记录并保留其余记录。等待是正常结果，世界保持Ready且Tick继续提交；等待水不设自动丢弃或超时删除。

恢复资源不足、变更超限或内部故障不能被解释为“无目标”，也不能靠截断恢复批次、丢弃记录或覆盖材料规避；按公共合同进入相应故障处理。搜索访问集合按世界范围与半径交集有界预留，全部记录、快照、映射、候选及预留目标缓冲计入CPU峰值。

## 5. 计数、查询与显示

活动位置继续用D02的归属/BodyId/局部坐标键；暂存写入用独立的逻辑键`(暂存, 记录ID)`，绑定generation。暂存计源位置及新增记录两处；恢复计移除记录及目标位置两处；暂存蒸汽寿命更新或自然消散计记录键；同Tick同键多写去重。不成功的恢复尝试不计材料写入，纯位姿及派生缓存仍不计逐格写入。整个Tick使用同一个计数集合，不每批重置。

ChangeSet增加明确的“进入暂存”和“恢复到网格”原因，并携带源/目标与记录身份关联；暂存蒸汽到期仍归自然消散。活动显示差异仍比较Tick首末成功状态，D02实际写入计数不改为净差异计数。暂存记录及其寿命属于版本化权威快照，但不作为普通`CellHit`。

`QueryPoint/QueryRegion/QuerySegment`只命中活动主网格和材料体。`Remove/Replace/Ignite`也只作用于活动材料，不按原坐标修改隐藏记录；`Spawn`的占据判定仍看活动材料和真实固体，材料容量预检必须加上暂存数量。暂存锚点不保留空间占据权。诊断至少按同一提交版本提供活动网格数、体内数、暂存水数、暂存蒸汽数和逐材料总数，不能把“查不到/画面看不到”报告成材料丢失。故障候选的计数只能作为标明workingTick的故障诊断。

M07B在成功暂存提交后清源纹素，隐藏记录不生成材料或火焰；成功恢复后显示目标纹素。查询、ChangeSet、逻辑显示和帧末GPU版本继续遵守原合同。其他故障仍保留最后成功画面，不显示失败候选。

Create的Tick0暂存集合为空。Reset释放旧集合并从保存的编辑初态重建，新generation的Tick0没有旧暂存记录；Dispose、退出试玩和失败创建按拥有者释放记录及缓冲。场景JSON仍只存初态，不保存暂存集合、记录身份或中途寿命，不新增运行存档。

## 8. 本轮冻结的共享接口

公共类型定义在`Core/Contracts/FluidSuspension.cs`；没有增加CellState字段或配置键。`OwnerKind.Suspended=2`的`CellPositionKey`使用BodyId字段承载独立域的暂存记录ID，X/Y固定为0；记录原坐标只存在于`SuspendedFluidSnapshot.OriginalPosition`。暂存键供内部读取、实例映射和D02计数，不允许空间查询产生该归属的CellHit。

```csharp
SuspendedFluidSnapshot(ulong generation, ulong recordId, Vector2Int originalPosition,
    ulong suspendedTick, CellSnapshot state);
// 同工作/候选/提交视图的租约；数据只读，OccupiedCells仍仅含活动材料。
IFluidSuspensionView.SuspendedFluids : ReadOnlySpan<SuspendedFluidSnapshot>;
// IWorld新增只读数量诊断；实现只消费最近一次成功提交快照。
MaterialCountsResult IWorld.QueryMaterialCounts();
```

`MaterialCountsResult`带Result、Version、GridCells、BodyCells、SuspendedWaterCells、SuspendedSteamCells和派生的活动/暂存/总数；Counts按MaterialId升序，逐项列GridCells、BodyCells、SuspendedCells、TotalCells。它是不可变值快照，内部数组仅通过ReadOnlySpan提供，可保存过去版本的计数；世界下一次提交、Reset或Dispose不会改写已经返回的数量结果。工作/候选/提交的暂存记录视图仍按原租约失效，不能把两种有效期混淆。

诊断在Ready与Faulted可读取最近成功版本；Faulted不暴露内部工作候选，Disposed返回Disposed，执行中重入返回Busy，提交通知可读当前成功版本。`CellChangeKind`末尾增加Suspended、Restored，BeforeKey/AfterKey关联活动格与记录身份，暂存记录不进入BodyIdMapping或可见DirtyRanges。`FailurePoint`末尾增加BeforeFluidCapture、BeforeFluidRestoration，用于分别验证资源失败不发布。

M06保留已有`FluidDisplacementPlanner`类型及文件名，以`CollectCovered`和`PlanRestoration`替代旧Plan入口；前者不选空位，后者只读最终占据并允许正常等待。M02内部`PreparePhysics`接受覆盖源CellKey批次，与完整位姿共同准备；`PrepareFluidMoves`统一准备暂存或恢复迁移。全部暂存记录/元数据、实例、写入计数及预算由同一PreparedGridMutation一次采用。
