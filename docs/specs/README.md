## 1. 如何派发

1. 所有 agent 先读本页、[公共合同](CONTRACTS.md)，再读领取的 spec 和其中引用的主方案章节。
2. 复用已落地的 M00 公共类型、测试装配和规格夹具，依据下表领取剩余阶段；新增共享字段或服务缺口由 M00 角色集中补齐。不得重复建设同名接口。
3. 每次派发明确 spec、阶段、可修改文件和交付证据；只交付模块核心时，状态写“核心完成，集成待验”，不能写整个模块通过。
4. 当前分工中的“集成负责人”是工作角色，由领取 M02 的 agent 承担；不代表已认领的人力或工期。其独占 WorldSimulation、WorldHost 的装配和推进代码。
5. 每个模块交回源码、必要资产、测试记录、接口变更和剩余事项。代码可编译、桩测试通过、Unity 实测通过必须分开记录。

可直接复制的派发指令：

```text
请执行 docs/specs/<模块文件>.md 的 <阶段>。
先阅读 docs/specs/README.md、CONTRACTS.md 及 spec 引用的主方案。
检查当前代码和未提交改动；仅编辑本模块负责的文件。
按验收编号实现并记录实际结果；不能运行的检查注明未测与原因。
公共类型有缺口时，给 M00/M02 负责人提交具体接口差异，不另建平行接口。
交接时列出文件、已满足条款、测试证据、集成需求和剩余风险。
禁止批量删除文件或目录；文档及批准请求使用中文。
```

## 6. 统一完成标准

- 条款有对应实现与验收编号；测试报告区分通过、失败、未测，不以计划文字当证据。
- 模块错误保留阶段、字段/目标及错误码；自动规则失败、命令拒绝和整个世界 Faulted 的边界符合公共合同。
- 必须包含越界、容量、失败清理及资源所有权检查；不得只测成功路径。
- 共享类型变动先更新公共合同和依赖方；改变可观察行为时同步主方案、Schema、示例和测试预期。
