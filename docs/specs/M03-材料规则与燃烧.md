## 1. 目标与非目标

实现 `liquid_flow`、`gas_drift`、`burnable` 的批次规则，以及 `extinguishes_fire` 的能力查询。规则读取阶段快照、返回意图，使调度器能够以固定顺序执行移动、寿命、燃烧、传播和熄灭。标签排列不得改变行为；材料 ID 不写死在规则中。

本任务不直接写主网格或动态体，不提交结构、物理、查询、显示和公开事件；不改 `WorldSimulation` 的调度代码。无蒸发、冷凝、压力、浮力、烟灰、耗氧、格内缩小和连续质量损失。`structure` 的连通行为由 M04 完成，火焰显示由 M07B 完成。

## 4. 输入输出合同

### 4.1 规则上下文

输入至少含阶段只读快照、共享材料表、`workingTick`、`stepSeconds`、`seed`、世界边界、固体占据查询、精确接触查询、本 Tick 湿集合和调用方拥有的输出缓冲。主网格按 `y/x` 排序，动态体按 `BodyId/局部 y/x` 排序。规则不能依赖字典枚举、系统时间、反射或每格对象实例。

每一阶段只读自己的开始快照。水阶段提交后，蒸汽阶段读取更新后的快照；燃烧阶段在移动后湿接触已经合并并熄灭后开始。输出是可预检的完整意图集合，不能输出“前半部分成功”；缓冲或预算不足须返回明确失败，由调度器决定命令拒绝或世界 `Faulted`。

规则统一实现 `IRuleExecutor.Execute(snapshot, materials, instances, contacts, in context)`；通过现有 `ITickInstanceMap.TryGetInstance(in CellKey,out CellInstanceHandle)` 获取当前实例，通过IsWet消费湿集合。实例表由M02传入，规则不调用其创建、迁移、失效或标湿方法。若已占据源缺少有效句柄，返回带阶段/格键诊断的失败批次，不能用default句柄或重新创建实例继续。执行器不得保留旧签名、强制转换WorkingWorld或复制身份表；新签名和有效期以CONTRACTS D01补充为准。

M00 必须先明确以下公共细节：

1. 规则意图如何引用同一材料实例；湿集合在搬运、提取及拆分时如何迁移。不能把可复用坐标或已撤销的 `BodyId` 当永久实例身份。
2. `maxChangesPerTick` 对倒计时、燃料、寿命、搬运源/目标及归属转移的计数键；状态变化不能遗漏预算。
3. 落实D04（1.7）：水先选原子液体链，普通重力候选与蒸汽保留原奇偶平局；水的横向候选须先按M03-L01判断扩散依据和方向，不能无条件按奇偶左右试走。同级按目标`y/x`、源`y/x`决胜，不把左右两候选合成同级。
4. 意图冲突与提交规则：新点燃目标若已在同批燃尽/移除，不能重新生成材料；多个点燃源只能修改目标一次。

这些是开发前的合同冻结项，不是新增玩法需求。以公共合同最终记录为准。

### 4.2 水与蒸汽

F01暂存不进入活动水流/L01链、普通气体移动或邻域；移动倒计时暂停、完整余量恢复。蒸汽寿命阶段同时处理活动与暂存记录，各实例本Tick恰扣一次；到0为自然消散。新暂存发生在寿命阶段之后，恢复发生在最终物理阶段且不再次扣寿命/移动；恢复后的精确水接触仍执行当Tick灭火。状态意图由M03产出、记录身份和受控采用由M02负责，详见[M06-F01](M06-F01-水汽暂存与恢复.md)。

`MoveCountdown > 0` 先减一；减后为 0 时可以尝试移动。尝试成功或全部受阻均重置为配置间隔。创建时为 0，间隔 2 对应 Tick 1、3、5；间隔 3 对应 Tick 1、4、7。

水先按M03-L01选取自由表面到较低原空终点的完整原子液体链；余下源再考虑下、首选斜下、次选斜下和有效横向候选。开放平底水槽必须摊平、平台积水必须能流向低处，已平衡水层应停止无效搬运；方向选择、防往返、固定期限与夹具按[M03-L01](M03-L01-液体扩散与液面平衡.md)执行。水斜下平局仍使用`(workingTick + x + y + seed)`偶数先左、奇数先右，不能将该公式无条件用于每步横移。

蒸汽保持上、首选斜上、次选斜上、首选水平、次选水平五层及原奇偶左右选择。奇偶计算不能受整数溢出影响。水汽的实际步长均为相邻一格、在逻辑范围内、不被真实固体占据遮挡。普通目标须阶段原空；原子水链可进入本链下一源，链尾必须原空且低于链首；斜移的对应水平侧格必须可通行。水汽不交换；除完整原子水链外，不利用同阶段新腾出的格，不越过封闭墙角。远处搜索仅指导方向，不允许多格瞬移。

每个源最多一次成功移动，每个目标最多一个获胜源；同级失败者可试更低优先级。成功搬运保留全部 `CellState`，由提交器清源和写目标，跨块与块内采用相同逻辑。

蒸汽寿命每 Tick 减一，与移动成功、受阻或间隔无关；降为 0 产生自然消散意图，不再移动。Tick 内通过 Spawn 新建的蒸汽也进入随后蒸汽阶段；除非公共合同明确更改，不为新蒸汽额外增加一 Tick 寿命。

### 4.3 燃烧、点燃与灭火

只有带 `burnable` 且余量大于 0 的格能够点燃。点燃记录当前工作 Tick；只有 `Burning && IgnitedTick < workingTick` 的格在本步消耗和传播。初始燃烧为 `IgnitedTick=0`，从 Tick 1 开始消耗。重复点燃正在燃烧的格不改变燃料或传播周期。

已有火先扣一单位燃料；到 0 产生燃尽移除且本步不传播。仍有燃料时传播倒计时减一，到 0 向全部有效接触的可燃格提出点燃意图，并重置传播周期。目标从下一 Tick 才开始消耗、传播；不得在扫描中递归推进火势。

湿集合在流动前建立、流动后合并，本 Tick 只增加。燃烧前湿格先熄灭，并丢弃本步点燃意图；清 `Burning` 与 `IgnitedTick`，重置传播周期，保留剩余燃料。物理阶段新增湿接触立即产生熄灭，不能追溯撤销此前已经完成的本步燃料消耗。

同归属使用四邻接，角点不接触。跨归属的 OBB 精确接触由 M06 提供，M03 消费结果；不得用 AABB 或 Unity 接触回调代替该合同。水不因灭火消耗或变为蒸汽。燃料尚大于 0 时格的占据、质量和碰撞完整保留，燃尽由统一提交链移除。

## 5. 实现检查项

- 执行入口按稳定 RuleId/RuleMask 绑定；`kind` 只分类，不能绕过标签隐式执行行为。
- `extinguishes_fire` 是邻格能力，不额外全图遍历；没有该能力的液体不能因名字或 ID 被当作水灭火。
- 每阶段候选读同一快照；调度器依次调用，规则和解析器不拥有世界状态。
- 纯规则代码不调用 Rigidbody、Mesh、Texture、GameObject，不在工作阶段触发用户回调。
- 意图区分自然消散、燃尽、状态改变和搬运，供 M02 维护逐材料守恒与 ChangeSet。
- 燃尽、Replace 和 Remove 后不保留旧燃烧状态；提取拆分只搬运状态，不重新初始化燃料。
- 扫描、候选、已处理源、预留目标及湿集合使用受预算约束的复用缓冲；稳态路径不得逐格分配。
- 使用配置的 Tick 参数，不能同时扣秒数或按渲染帧更新。避免未定义的 unsigned 下溢。
