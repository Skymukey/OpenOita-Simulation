## 目标与边界

交付可编译的公共值类型/服务边界、测试程序集、固定场景生成器、实际环境记录和规格差异记录。接口只有定义时不能提供假成功的生产实现。不得顺带重写原型、增加玩法、估造人日或承诺原截止日期。

## 文件归属

- 负责 `Assets/Scripts/OpenOitaWorld/Core/Contracts/` 下公共类型及项目所需的最小运行时 asmdef；测试装配位于 `Assets/Tests/OpenOita/`，按 EditMode、PlayMode 分离。
- 负责 `Assets/Tests/OpenOita/Fixtures/` 中初态/命令/专用物理状态夹具，以及 `docs/validation/` 的环境、基线差异、结果模板。
- 公共合同的类型字段、错误码、版本和服务边界由本任务冻结。已有 CellState 的实际迁移归 M02，材料解析归 M01，Host 接线归 M02。
- 不批量生成或手工猜测 Unity GUID；使用项目既有资产机制保留引用。不得改 Library/Temp/生成的 csproj 来代替正确装配。

## 必须交付的合同

1. 将 CONTRACTS C03 的类型表映射到真实类/结构体与文件，覆盖配置、状态身份、阶段意图、结构计划、准备对象、版本快照、公共结果。每个接口明确拥有者、可变性、有效期及失败行为。
2. 公共外部入口以主方案7节签名为准；错误集合完整，BodyId、generation、Tick、CommandToken 可检查溢出和过期，不把所有错误折为false。
3. 固定D01–D10及F01暂存记录身份、只读视图、计数键、变更原因、诊断和租约；在编码前集中冻结共享签名，不让各模块建立平行接口。固定 D01–D10：湿集合映射、变更去重键、BodyId顺序、候选层级、查询边界/排序、静态形状预算、子步估计、故障令牌和重复Replace。专用夹具不得要求新增公开速度或冲量API。
4. 准备/应用/发布是三个不同阶段。定义可失败准备句柄、只读工作输入、旧新体映射、所有资源清理责任。正式代码不能通过查询持有可写世界数组。
5. 冻结 `SceneInitialData`（运行时不可变初态）和 `SceneMaterialData`（编辑模型）的转换边界；序列化归M01、编辑模型归M08。
6. 按CONTRACTS 1.5的C01冻结逻辑像素、独立状态、原始纹素及屏幕倍率的区分。提供可复用的逐像素夹具：8×8独立材料、相邻像素差异状态、单像素空洞、跨127/128边界以及轴对齐／旋转体；不新增逐像素GameObject或随屏幕分辨率改变状态的接口。逐像素夹具及独立模块预览的Editor验证见[整改记录](../validation/像素粒度-整改与验证.md)；后续正式显示、旋转查询及编辑试玩Editor证据见[M07记录](../validation/M07-命令查询与显示实现验证.md)、[M08记录](../validation/M08-编辑器与保存实现验证.md)，完整Player出口仍待验。

## 实施步骤

1. 记录当前 git 差异、Unity 6000.3.11f1、目标Windows平台、测试包与解析器实际依赖、现有场景引用。保留用户已有修改。
2. 核对三份示例和Schema；场景应为175材料格、2固定点、1初燃点。正例来自这些文件，反例必须是独立副本，不修改基线样例制造失败。
3. 复核 Newtonsoft 实际依赖与 CONTRACTS C11 一致：历史3.2.2间接依赖已由M01改为直接锁3.2.1，见[M01记录](../validation/M01-执行结果与交接.md)。后续变更继续采用C11流程，不重复执行已完成的安装决策。
4. 添加最小程序集边界并检查旧全局类型、Editor引用和测试可见性。运行时代码不可依赖UnityEditor，内部测试入口只对测试程序集可见。
5. 定义公共类型，形成可编译消费者桩；桩只在测试中使用。与模块负责人核对输入/输出字段后再进入并行开发。
6. 为T1–T9与P1–P4建立确定生成器或数据文件；记录坐标、材料、固定点、初燃点、专用配置差异、命令次序、观察阶段和预期。测试用的小尺寸世界仍使用128块长。
7. 提供中文验证模板，字段至少包含：验收ID、实现/配置版本、Unity/后端、实际机器、构建、命令/初态、运行方式、预期/实际、结果、日志路径、未测原因。
