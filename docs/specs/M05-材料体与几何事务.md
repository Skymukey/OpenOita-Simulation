## 1. 目标与非目标

把 M04 输出的全部连通分量转成固定结构或独立材料体，完成自动提取、体内编辑后的再次拆分、真实占据矩形几何、质量与惯量计算，以及结构变更的整体准备和提交。每个非空自由分量均保留，包括一格碎片。

不实现连通查找器、不直接调度 Tick、不定义第二套公共命令 API，也不推进 Unity 物理。无最小碎片丢弃、散粒退化、接触焊接、应力或额外冲量。物理对象由 M06 创建和管理；显示资源由 M07B 管理。

## 4. 输入、输出与所有权

输入必须来自候选工作世界：本次命令或已裁决规则批次、完整旧格状态、固定点信息、M04 的 `StructurePlan`（全部分量、固定结果与稳定成员顺序）、旧材料体位姿/速度、材料质量表、配置预算与变更计数。不能从渲染纹理或旋转后的世界采样恢复材料。

建议输出为不公开的 `PreparedMaterialMutation`，内含 `BodyGeometryPlan`，至少包含：

- 主网格移出/保留与目标体局部格；全部适用 `CellState`、材料实例身份和归属转移记录。
- 创建、更新、撤销的 BodyId，旧新 BodyId 映射、局部几何原点、连续位姿与几何版本。
- 每个固定/动态结果的无重叠矩形列表、质量、局部质心、惯量和继承速度。
- 材料格、动态体、单体形状、静态及动态总形状、不同权威格写入数、临时资源的完整预算核算。
- M06 物理与索引准备请求、M07B 显示关联变更请求，以及失败诊断和可释放的临时资源。

`PreparedMaterialMutation` 只能经 M02 的统一工作事务提交，不能与 M04 输入 `StructurePlan` 混为同一对象。结构提交成功也不等于 Tick 已公开成功；只有物理等后续阶段全部成功，才由 M02 发布版本与 `ChangeSet`。准备缓冲、已提交材料体及下游资源的释放责任必须分别明确。

CONTRACTS 1.4已冻结实际接线：`MaterialMutationPreparer`消费原IPreparedMutation的CandidateWorld/CandidateInstances/CandidateWrites；通过MaterialOwnershipPreparation将全部PlannedCell、BodyIdMapping、几何、IMaterialBodyStorage及撤销ID移交M02。成功返回同一候选的IPreparedMaterialMutation，协调器不能将原编辑和返回结果当成两个参与者。M05不写实例、计数或世界；存储移交成功后不再由计算计划Dispose。Spawn、Move、同ID Replace均以候选句柄为准，湿标记随原实例迁移，Replace用新干实例。Tick0初始化同样使用真实候选租约，不自行创建平行实例表。

## 5. 实现检查项

### 5.1 自动提取与 BodyId

1. 初始化、结构增删替换和燃尽均检查 M04 提供的全部分量。主网格分量只要仍连接到有效固定格就保留；每个自由分量自动成为材料体，不需要人工预登记。
2. 主网格自由分量全部分配新 BodyId，不能继承主网格的 0。原动态材料体剩一个非空分量时保留原 BodyId；剩多个分量时撤销原 BodyId，给全部结果分配新 ID；变空时撤销。准备阶段可预留 ID，事务提交后进入工作状态，成功 Tick 时才公开；准备失败的预留号也不得复用。BodyId 在同一 generation 内不复用。
3. 分量、格和 ID 分配遵守公共合同 D03：按原归属键（主网格先、再旧 BodyId），随后按分量最小局部 y/x 排序。最小坐标在原归属坐标系、重定新体局部原点之前取得，不依赖 Dictionary 遍历。不同连接组不得被合并为一个连通体。

   M05-I01已补齐：原 `IMaterialMutationPreparer.Prepare` 必需接收M02的 `BodyIdReservation reserveBodyIds`，当前签名见CONTRACTS 1.4，ID错误边界沿用1.3。统计ExtractFreeGrid/CreateChildBody总数并预检已知预算后，通过 `ReserveBodyIds(count, destination)` 一次预留，按既有Components顺序消费；固定网格和保留体不耗号。M05计算核心继续只消费预留数组，不拥有序列。历史验证见 [BodyId接口补齐记录](../validation/M00-M05-I01-接口补齐与验证.md)；候选实例及受控材料归属提交现已补齐，物理与显示事务仍待集成。
4. 主网格、任一材料体及M02暂存记录对材料格实行唯一所有权；暂存不进入结构连通、碰撞、体质量或提取计划，但完整候选世界材料预算必须包含暂存；提取/拆分搬运完整状态，不能重新初始化燃料、燃烧时刻、寿命或倒计时。固定标记失效遵守 M04 输出，不因新材料占据原坐标而继承旧标记。
5. 动态体局部格为权威表示；世界占据、碰撞和显示由它派生。不得反复把旋转格采样回主网格。
6. 动态体 Replace 仅允许 structure 固体；替换水/蒸汽按公共命令合同整条返回 `UnsupportedOperation`。预检必须在原体变更之前发现。

### 5.2 矩形几何

1. 从最小局部 y/x 的未覆盖格开始，沿 x 扩展连续非空区间，再沿 y 扩展同宽、未覆盖且均非空的行，覆盖后继续。
2. 可跨材料种类合并，但不跨不相连的材料体。所有非空格恰好被覆盖一次，矩形互不重叠，不覆盖孔洞。
3. 固定结构同样按真实占据生成矩形，纳入 `maxTotalShapes`；每个动态体纳入 `maxShapesPerBody`。固定 4 个世界边界形状由 M06 独立计数，不占材料形状预算。
4. 一个矩形对应一个 `BoxCollider2D` 的请求，同体共享一个刚体。M05 交付数据，M06 执行 Unity 对象操作。
5. 不以凸包、大包围盒或填孔方案减少形状。预算不足执行拒绝或 Faulted 分支，不降级成错误几何。

### 5.3 质量、质心与速度

设材料格质量为 `m_i`，格中心为 `c_i`，格边长为 `s`：

```text
M = Σ m_i
c = Σ(m_i × c_i) / M
I = Σ(m_i × s² / 6 + m_i × |c_i - c|²)
v_new = v_old + omega × (c_new_world - c_old_world)
omega_new = omega_old
```

计算质心时使用统一坐标空间；速度公式使用世界质心。内部角速度为弧度/秒，二维叉乘为 `(-omega × dy, omega × dx)`。

局部几何原点与质心分开保存；改变质心不得平移现存材料格。拆分、删端格、燃尽以及替换异材即使保留 BodyId，也重算质量/质心/惯量，并应用相同速度场公式。燃料仍大于 0 时材料格保持完整占据、质量与碰撞；燃尽到 0 才统一移除。

下游 M06 关闭自动质量计算，显式应用 `mass`、`centerOfMass`、`inertia` 后恢复速度。不得按矩形数量推导质量，也不得添加补偿冲量。

### 5.4 结构事务与预算

1. 先取得完整修改集合与全部分量，再计算全部结果体、静态几何、质量、占据索引和显示关联；阶段内不能边发现分量边发布新体。
2. 使用溢出安全运算预检最终预算和临时工作资源。`maxChangesPerTick` 遵守公共合同 D02，由 M00/M02 的统一计数器按不同权威位置键去重；状态、材料实例或归属任一变化都计入，同材料 Replace 即使状态字节相同也计该位置。搬运及提取/拆分计源和目标的旧、新归属位置；整个 Tick 共用累计集合，不能每批重置，也不能仅按调用次数或矩形数计算。纯位姿和派生缓存更新不计逐格写入。
3. 只在所有准备成功后共同提交到工作世界。物理/索引/显示准备失败时释放全部临时结果；旧格、旧体、约束及碰撞保持本条事务前的状态。
4. 旧碰撞必须在后续物理解算前被撤销或禁用，不能依赖 Unity 延迟销毁使它“随后消失”。
5. 外部命令超预算时整条拒绝，返回 `CapacityExceeded`，不产生部分体。自动规则无法满足预算时由 M02 进入 `Faulted`，不发布成功 Tick。
6. 不承诺整个 Tick 或物理解算器回滚。若后续阶段失败，禁止公开工作状态；显示保留最后成功版本，普通材料查询禁用，允许 Reset/Dispose 恢复或关闭。
7. `ChangeSet` 把归属转移与真正生成/移除/燃尽分开。提取、拆分不应减少逐材料格数；状态搬运不能计作消耗。
