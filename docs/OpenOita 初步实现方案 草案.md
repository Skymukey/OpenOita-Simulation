### 材料规则

用户已确认：燃烧是一种规则，**可点燃、传播、烧损，遇水熄灭，燃尽消失；无烟、灰和耗氧**。火焰是附着显示，不是第五种材料。全部材料从一个 JSON 文件加载；主网格在逻辑上是“坐标 → 材料类型”映射；材料以标签关联规则。

本轮把其余常规选择定为以下技术默认，供实现和测试使用，参数可调整，不表示用户逐项确认了数值：

- 水通过原子液体链及普通下、斜下、横向单格移动扩散；链内可进入同链下一源，末端须原空且更低；开放平底槽中应摊平，平台上的水应流向可达低处，平衡后停止无效往返。边界与固体仍阻挡；不模拟压力、浮力或流体对刚体的反作用力。
- 蒸汽向上、斜上或横向进入空格，达到寿命后消散。初始布局或 Spawn 产生蒸汽；首版不自动蒸发、冷凝。
- 木头与混凝土按四邻接、相同连接组构成结构。接触中的独立刚体不自动焊接。
- 最小碎片为一格，每个非空分量都保留为刚体；不引入散粒分支，也不因碎片太小而丢弃。
- 首版提供 Unity Scene 自定义画笔、擦除、固定标记、初始燃烧标记、预览与保存加载。运行时画笔、撤销重做及高级笔刷列为后续扩展。
- 不包含烟灰材料或烟灰效果、耗氧、应力、弯曲、承载过载断裂、角色推挤、公开爆炸冲量接口和大世界优化。

### 2.2 材料定义

根对象必须包含 schemaVersion=1、materialSetId 和 materials 数组。当前集合为 openoita-core-v1。

| 字段 | 合同 |
| --- | --- |
| id | 1–65535 的整数；全文件唯一、发布后不改变其材料含义 |
| name | 非空名称，全文件唯一；首版按大小写敏感序数比较 |
| kind | solid、liquid、gas；仅描述分类并校验标签适用性，不自动启用任何规则 |
| color | #RRGGBB；共享显示颜色，不逐格复制 |
| massPerCell | 有限正数，单位为每格游戏质量；只对固体参与刚体质量计算 |
| tags | 不重复的已注册标签名称；拼写区分大小写 |
| ruleParameters | 按标签名组织的参数块；所需块必须提供，无对应标签的块拒绝 |

v1 要求 solid 显式包含 structure、liquid 显式包含 liquid_flow、gas 显式包含 gas_drift。缺少标签时报错，不能依赖 kind 暗中补行为。材料可组合兼容的能力标签；新增未注册行为仍需增加 C# 实现。

| 标签及 RuleId | 位标记 | 适用 kind | 触发方式 | 必需参数与默认样例 |
| --- | --- | --- | --- | --- |
| structure / 1 | 1 << 0 | solid | 材料变化后的连通检查 | connectionGroup="building" |
| liquid_flow / 2 | 1 << 1 | liquid | 流动阶段逐格更新 | moveIntervalTicks=2 |
| gas_drift / 3 | 1 << 2 | gas | 每 Tick 更新寿命，到间隔时移动 | moveIntervalTicks=3、lifetimeTicks=200 |
| burnable / 4 | 1 << 3 | solid | 允许 Ignite；已燃烧格执行燃烧阶段 | fuelTicks=250、spreadIntervalTicks=10 |
| extinguishes_fire / 5 | 1 << 4 | liquid | 供邻格燃烧规则查询的能力，不独立遍历一次 | 无参数块 |

connectionGroup 为非空字符串。时间参数均为 1–1,000,000 的整数 Tick；换算秒数为 Tick 数乘 stepSeconds。当前默认木头燃烧总余量 250 Tick，即 5 秒，每 10 个实际燃烧 Tick 尝试传播。改变固定步长需同步修改时间参数，不在运行中改变步长。

RuleRegistry 在加载时将名称转换为稳定 RuleId、ulong RuleMask、参数索引和阶段入口；位号为 RuleId−1，v1 未注册的位拒绝。64 位容量不足时升级格式与实现，不能截断。标签顺序无语义，排列变化不能改变模拟结果。

### 2.3 世界配置与预算

世界、材料、布局分别保存。Host 显式接收这三份文本或已读取数据，文件解析器不扫描 Assets 目录。PC 包的启动入口将三个文件部署在同一配置目录，读取文件后调用同一创建流程；编辑器也使用该流程。

| 配置 | 首版默认 | 约束及含义 |
| --- | ---: | --- |
| width、height | 256、256 | 逻辑像素数，1–4096；每像素一份独立状态，按总格数与容量检查，不因维度合法就承诺规模 |
| chunkSize | 128 | 存储区块边长，单位为逻辑像素；v1 固定，内部仍逐像素模拟，尾块超出逻辑尺寸的格不可写 |
| cellSize | 0.1 | 有限正数，单位为 Unity 世界单位／逻辑像素；不表示屏幕像素大小或显示倍率 |

| gravityY | -9.81 | 有限数，仅刚体使用；网格移动方向由规则定义 |
| seed | 1 | uint32；用于稳定左右选择，不从系统时间取随机数 |
| maxMaterialCells | 65536 | 主网格、全部动态体和暂存集合的非空材料总数 |
| maxDynamicBodies | 64 | 同时存在的动态材料体数 |
| maxShapesPerBody | 256 | 单体矩形碰撞形状数 |
| maxTotalShapes | 4096 | 静态及动态材料矩形形状总数，另有固定4个世界边界形状 |

| maxLinearSpeed | 5 | 世界单位／秒，刚体能力上限 |
| maxAngularSpeedDegrees | 180 | 度／秒，刚体能力上限 |

### 2.4 校验与版本

读取一次后依次执行：JSON 语法与重复键检查 → Schema 等价字段校验 → 跨条目／跨文件语义校验 → 建立临时材料表与布局 → 准备结构、物理及显示 → Ready。任一阶段失败都不发布部分注册表。

M1 采用 Unity 的 com.unity.nuget.newtonsoft-json 3.2.1 包作为解析依赖，实施时写入并锁定包清单；本轮只确定方案，尚未安装。先用 JObject.Load 和 JsonLoadSettings 将 DuplicatePropertyNameHandling 设为 Error，再按字段白名单、JSON 类型和取值范围校验，转换到明确 DTO；禁止按输入类型名实例化对象，TypeNameHandling=None。不能仅用当前 JsonUtility 直接反序列化来宣称完成严格校验。[Unity 包说明](https://docs.unity.cn/Packages/com.unity.nuget.newtonsoft-json%403.2/manual/index.html)、[重复键处理选项](https://www.newtonsoft.com/json/help/html/P_Newtonsoft_Json_Linq_JsonLoadSettings_DuplicatePropertyNameHandling.htm)。

未知 JSON 键、未知标签、错配参数块、不兼容 kind、重复 ID/name、非有限数、无效引用和不支持的版本全部报错。缺省值只用于本文明确说明的运行状态初始化，不擅自补缺失的配置字段。

Schema 不能代替以下校验：跨材料 ID/name 唯一、地图坐标唯一且在实际范围内、材料集合一致、固定点及初燃点适用性、总预算关系、乘积溢出，以及 JSON 解析器是否拒绝重复键和非有限数。

materialSetId 标识材料 ID 的语义集合。修改颜色或调节参数不重排 ID；更换 ID 含义或不兼容定义时升级 materialSetId，旧地图默认拒绝并给出迁移诊断，不按名称猜测替换。schemaVersion 只标识格式。首版不做热加载；修改后重新 Create／Reset。

## 3. 存储与单格状态

主网格逻辑接口为“坐标 → 材料 ID”。底层使用区块坐标字典定位已存在的 WorldChunk，块内使用连续 NativeArray<CellState>，索引为 y×128+x。合法缺块查询返回空，不创建区块。地图保存 ID，不保存材料对象、字符串标签或规则对象。

本方案的“一格”就是一个逻辑像素，每个坐标具有独立材料及适用规则状态；Chunk、碰撞矩形和材料体不得把多个像素合成一份材料状态。固体像素共用刚体位姿仍保留逐像素编辑与规则，显示映射按5.3节执行。

材料加载为共享运行表，另建 65536 项的 ushort ID→紧凑索引表；索引 0 为无定义／空，非空引用必须能解析。每格只存 ID 与可变状态。现有 MaterialIds 数组改为派生显示缓存，以完整CellState为唯一事实源，活动网格、体内与暂存的存储归属按3.2节执行。

### 3.1 CellState 字段

| 字段 | 类型 | 初值与用途 |
| --- | --- | --- |
| MaterialId | ushort | 空为 0，非空为配置 ID |
| Flags | ushort | bit 0=Burning；其他位为 0，v1 不复用作可燃标签 |
| FuelTicksRemaining | uint | burnable 从 fuelTicks 初始化，其他为 0 |
| SpreadCountdown | uint | burnable 从 spreadIntervalTicks 初始化，其他为 0 |
| LifetimeTicksRemaining | uint | gas_drift 从 lifetimeTicks 初始化，其他为 0 |
| MoveCountdown | uint | 创建为 0，表示第一次规则阶段可移动 |
| IgnitedTick | ulong | 首次点燃时记录当前工作 Tick；初始燃烧为 0，未燃烧为 0 |

字段按满足对齐的顺序排布，设计内存预算按每格不超过 32 字节；实现后分别在 Editor 与 Player 验证实际大小。首版网格水汽采用离散移动，不依赖逐格 Velocity；动态固体的线速度、角速度属于 MaterialBody。现有 CellState.Velocity 的迁移在 M2 完成。

burnable 是共享能力，Burning 是单格状态。熄灭只清 Burning、IgnitedTick 并重置 SpreadCountdown，保留 FuelTicksRemaining；不会修复已经发生的烧损。再次 Ignite 使用剩余余量。重复点燃已燃烧格是无变化操作，不刷新余量或传播周期。

烧损每有效燃烧 Tick 扣一单位余量，余量用于颜色变暗等显示；余量仍大于 0 时，该格继续保持完整占据、单格质量和碰撞。余量降为 0 时材料格变空，统一更新结构、质量和碰撞。这是首版逐格烧损精度，不模拟格内缩小或连续质量损耗。

Lifetime 每 Tick 减一，与是否移动无关；为 0 时蒸汽移除并记录自然消散。Replace 初始化新材料全部状态；Remove 置空；搬运、提取、拆分保留全部适用状态；Reset 按编辑初态重新初始化。

扫描访问集合、候选写入、已移动集合和本 Tick 湿接触集合是临时工作数据，不写入关卡存档。燃烧格满足 Burning 且 IgnitedTick < workingTick 时才消耗和传播，阻止新点燃格在同一步继续连锁推进。

内部接口落实见CONTRACTS 1.1：规则通过M02传入的同Tick实例表查询当前格的材料实例与湿标记，并只返回引用该实例的意图；实例迁移、替换、撤销及标湿归M02受控阶段。`ITickInstanceMap.TryGetInstance`只查已登记实例，`IRuleExecutor.Execute`必需接收该实例表，不从坐标生成平行身份。这是实现签名补齐，不改变文件格式、规则参数或玩法语义。

### 3.2 所有权与守恒

每份非空材料只能属于主网格、一个 MaterialBody 或一条M02持有的水汽暂存记录。暂存记录保留完整状态、原坐标、稳定身份和进入Tick，没有活动占据或显示；允许多条记录有相同原坐标。动态体保存局部格、BodyId、局部原点、连续位姿、速度和几何版本；世界占据、碰撞、查询索引和渲染均是派生表示，不反复回写旋转后的采样结果。

无显式生成、移除、燃尽或蒸汽消散时，逐材料数量守恒。燃料余量改变不改变格数。数量守恒按主网格＋全部材料体＋暂存逐材料核对。ChangeSet 分别记录生成、移除、燃尽、自然消散、进入暂存、恢复和归属转移；搬运、拆分、暂存与恢复不计作消耗。BodyId 在同一 generation 内不复用。

统一预留入口见CONTRACTS 1.3（M05-I01，承接M02-I02）：M02按generation持有唯一序列，以 `WorldResult ReserveBodyIds(int count, Span<ulong> destination)` 的BodyIdReservation回调作为原材料准备接口的必需输入。主网格ID=0，新体ID从1非零递增；全部新分量按原归属、原最小y/x顺序消费。成功预留后准备失败也不回收；完整号段不足返回CapacityExceeded且不写入部分结果，不能溢出回0。体7删中格形成两分量时撤销7并取得8、9，单分量则保留7。此为内部接口补齐，不修改材料ID、文件格式或玩法语义。

候选与归属提交见CONTRACTS 1.4（M05-I02/I03）：原准备对象提供编辑后的只读CandidateInstances和CandidateWrites；M05通过同一材料Prepare入口消费候选，并将完整体局部存储、归属映射及几何经M02受控回调合入原候选。全部参与者预检后，同一次Apply采用网格移出、体目录、固定/占据、实例迁移与整个Tick计数；同ID Replace使用新实例，Move和提取/拆分保留原实例及湿标记。工作应用与Tick发布仍分离，已提交体视图独立复制。正式物理、查询/显示及完整IWorld生命周期仍需后续接线验收。

## 4. 规则执行与确定顺序

RuleRegistry 的条目包含 RuleId、标签名、适用 kind、参数解析器、触发方式和阶段入口。固定 C# 系统按批次处理候选格，不为每格创建类实例，也不每 Tick 解析 JSON 或使用反射寻找执行器。

规则输入为只读阶段快照、共享材料表、邻域查询、workingTick 与步长；输出为候选移动、状态写入、点燃或移除意图。规则不能直接改公开数组、刚体或显示。调度器完成竞争裁决、容量预检及结构事务，再使该阶段变化进入工作状态。

所有排序使用明确的整数键。主网格按 y、x；体按 BodyId，再按局部 y、x。字典遍历顺序不参与结果。Tick 使用 ulong，推进前检查溢出；generation 在 Reset 时增加并检查溢出。

### 4.1 固定 Tick 流程

1. workingTick=committedTick+1，按令牌序号执行外部命令。新点燃格的 IgnitedTick 设为 workingTick。
2. 建立主网格／材料体的精确邻域，记录流动前的水接触。湿接触集合绑定材料实例，本 Tick 只增加，到下一 Tick 重新建立。
3. 基于当前工作状态生成水的移动候选，统一裁决并搬运。
4. 活动及暂存蒸汽每Tick各扣一次寿命，移除到期材料；只有活动蒸汽生成移动候选，暂存水汽的移动倒计时暂停。
5. 再计算移动后的水接触，合并到湿集合；先熄灭并抑制受水格的点燃。接触过的水随后流走也不会漏掉本步灭火。
6. 对阶段开始时已有且仍燃烧的格扣余量、更新传播周期，生成传播意图；燃尽移除。传播只写目标的点燃状态，目标从下一 Tick 开始消耗与传播。
7. 对规则材料变化准备全部连接、固定、拆分、质量及碰撞结果，预检成功后共同落地到工作世界；命令造成的结构变化已随各自事务预检并提交。
8. 推进物理子步；每子步校验边界、速度、占据，处理新的水接触并整批暂存被覆盖的活动水汽。全部子步成功后尝试恢复旧暂存记录并补充湿接触；新暂存最早下一Tick恢复。
9. 全部成功后发布 committedTick、查询版本与 ChangeSet，调用提交通知；帧末合并脏范围更新显示。

已在燃烧前接触水的格，本步不会传播或烧损。物理阶段因运动才新接触水的格立即熄灭，最迟本 Tick 发布时生效；不追溯撤销燃烧阶段此前完成的消耗。水不被灭火消耗，也不因此变为蒸汽。水接触在外部命令之后首次记录，因此同 Tick 先 Remove 水再 Ignite 可以重新点燃。

### 4.2 水与蒸汽移动

每阶段先将相应格 MoveCountdown 大于 0 的值减一；减后为 0 的格可以生成一次移动候选。成功或受阻都将倒计时设为配置间隔。间隔为 2 时首次移动在 Tick 1，此后在 3、5……；间隔为 3 时在 1、4、7……。

| 规则 | 按优先级尝试的目标 |
| --- | --- |
| liquid_flow | 原子液体链优先；余下源按下、斜下左／右、有依据的横向候选处理；每实例最多走一邻格 |
| gas_drift | 上；斜上左／右；水平左／右 |

水斜下与蒸汽的左右平局按(workingTick+x+y+seed)偶数先左、奇数先右。水的横向方向必须基于可达空通道及较低落点，不能仅按Tick/位置奇偶反复反向；完整行为、搜索落地关口及预算见[M03-L01](specs/M03-L01-液体扩散与液面平衡.md)。远处搜索只指导方向，每次实际仍移动一格。

目标必须在逻辑边界内且不被真实固体占据遮挡。普通目标须阶段原空；完整原子水链允许进入本链下一源，末端须原空且低于链首；斜移还要求对应水平侧格可通行，防止穿过封闭墙角。水、蒸汽首版不交换，原子链不能穿异材或固体；边界阻挡，无法移动则原地保留。封闭连通器压力均衡与向上顶升仍不在首版范围。

每个源最多提交一个移动，每个目标最多接收一个源。候选按偏好层级依次仲裁，同层按目标 y/x、源 y/x 决胜；失败源可尝试下一候选。除已预检的完整原子液体链外，同阶段不利用刚刚腾出的格；链只读阶段快照、统一预留提交，不允许依赖扫描写回顺序。水阶段先于气体阶段，气体读取水阶段提交后的快照。

TryMove/批次Prepare在写入前检查边界、占据、临时预留及容量。原子水链按M03-L01校验无环、同材、正交、尾空且净下降，候选实例尾到头迁移，最终清源和写目标统一合并；中间节点即使字节相同仍计身份变更。跨区块与块内使用同一裁决，不在块边界重复处理。

开放平底槽的平衡按全部内部列计算水深，干列计0，水层下不得有孔洞；深度差至多一格。固定1倍/8倍夹具分别要求在256/1024 Tick内达到几何平衡，随后128 Tick占据不变且无成功搬运；倒计时变化除外。平台、长通道、隔墙与地形开通另按[固定夹具](examples/液体平衡验收夹具.md)验收。这些是新增工程目标，尚未验证，不自动套用到任意地形或尺寸。

### 4.3 燃烧与接触

Ignite 和初始燃烧配置是首版点燃入口。只有 burnable 且 FuelTicksRemaining>0 的材料可点燃；非可燃材料不受影响。环境不自行升温点燃。

已有燃烧格先扣一燃料余量；若变为 0，生成燃尽移除，本格本 Tick 不再传播。仍有余量时 SpreadCountdown 减一，为 0 则向全部可接触的可燃目标提出点燃意图，再重置周期。多个源点燃同一目标只生效一次；已燃烧目标不重置状态；受水目标丢弃本次点燃意图。不计算随机概率、氧气、烟或灰。

同一主网格或同一 Body 内采用严格四邻接，角点接触不算。跨归属先用世界索引筛选，再计算真实格正方形的 OBB 最近特征距离：距离≤epsilon 且为边–边或顶点–边接触时有效，仅顶点–顶点相切无效；epsilon=1e-4×cellSize。正面积重叠也视为接触，但仍须执行占据合法性和流体暂存检查。AABB 只作筛选，不代替实际材料命中。

火焰由已提交 Burning 状态与位姿生成，不独立占格、计质量或参与碰撞。首版每个区块／动态体生成批量火焰四边形，使用独立材质统一时间动画，不为每格创建 GameObject。熄灭、燃尽、移除、替换、Reset 时清理相应显示。

## 5. 地图、编辑与保存

### 5.1 地图格式

scene.json 保存编辑初态：schemaVersion=1、materialSetId、materialsFile="materials.json"、worldConfig="world_config.json"、cells、fixedCells、initialBurning。v1 两个引用文件名固定为同目录名称，不接受任意路径。

cells 每项为 x、y、materialId；只保存非空格，按 y/x 升序排列，不允许重复坐标。fixedCells 和 initialBurning 保存 x、y，同样排序且不重复。未列出位置为空。坐标范围为 0≤x<width、0≤y<height。

固定点必须对应 structure 材料，初燃点必须对应 burnable 材料。固定标记绑定该格的材料实例，材料被 Remove 或 Replace 后旧标记失效；重新固定通过编辑布局实现。初始燃烧从满燃料、IgnitedTick=0 开始。

只保存编辑初态，不保存运行中的 BodyId、变换、已消耗燃料或中途存档。进入试玩建立副本，退出不回写；Reset 使用创建时保留的初态副本。编辑器保存采用同目录临时文件完整写入后替换目标，失败保留原文件并报告。

### 5.2 编辑器与坐标

使用自定义 Scene 画笔，直接编辑 SceneMaterialData；不依赖 Tilemap 存储。提供材料选择、单格／矩形画笔、擦除、固定标记、初始燃烧标记、网格预览、保存与加载。无固定连接的初态结构在进入运行时自动成为动态体。

X 向右、Y 向上；格中心为 origin+cellSize×(x+0.5,y+0.5)，点转格向下取整。范围左闭右开，空与越界区分。Host 旋转为 0、缩放为 1，运行中 origin 不变。动态体查询逆变换到局部检查实际非空格。

区域命令采用“实际材料格中心位于世界矩形内”作为选格标准；点查询检查实际格面，线段查询检查真实正方形交集并按沿线距离排序。选择矩形不因旋转体包围盒覆盖孔洞而命中孔洞。擦除预览使用与执行相同的选格函数。

### 5.3 像素粒度与显示约定

2026年10月5日补充，与[公共合同C01（1.5）](specs/CONTRACTS.md#c01-数据与坐标)共同约束后续实现。统一关系为：**一个逻辑像素 = 一个模拟格 = 一份独立材料状态 = 一个原始材料纹理像素**。屏幕像素只表示输出画面的采样点；改变窗口或视图倍率不改变模拟数据。

| 层次 | 含义及约束 |
| --- | --- |
| 逻辑像素／模拟格 | 最小材料单位；单像素查询、绘制、擦除、点燃与规则操作只能按实际命中坐标处理，不能隐式扩成2×2、8×8或一个Chunk。后续规则产生的传播等变化另按阶段记录。 |
| 原始材料纹素 | 主网格或体局部坐标逐像素生成颜色，空位透明。分块、图集或等价批量绘制保留这个映射；不能先降采样再放大冒充逐像素显示。 |
| 世界长度 | 一个逻辑像素边长为cellSize，初态主网格范围为width×cellSize、height×cellSize。增密同一世界范围需增加宽高并相应缩小cellSize、重新生成布局及检查预算。 |
| 屏幕显示 | 标准材料预览默认1:1，可显式选2倍、3倍等整数倍；k倍下一个逻辑像素显示为k×k画面像素，仍只有一份状态。窗口不够时裁剪／平移，不自动改变模拟宽高或拉伸填满。 |

精确像素视图采用Point采样，关闭会混合材料像素的mipmap、插值及后处理重采样，对齐主网格的屏幕边界。默认填满像素，不使用Inset制造格间缝；网格线、固定标记与几何框作为可关闭的调试叠加层，网格线默认关闭。编辑器自由视角或可选适应窗口视图显示实际倍率，并提供1:1恢复入口。验收截图使用未二次缩放的实际游戏输出；记录输出尺寸、倍率及叠加层状态，不能按GUI布局单位或缩略图测像素。

1:1屏幕覆盖断言适用于轴对齐且边界对齐的主网格；动态体连续旋转／平移仍按局部原始纹素显示，屏幕覆盖可能变化。不能为贴齐像素修改体位姿、材料坐标或将旋转采样结果写回状态。单像素编辑和查询仍沿用真实格几何及逆变换。

正式编辑、试玩和配置预览消费同一已校验world_config，尺寸与cellSize不被硬编码预览覆盖。独立模块探针明确显示自有逻辑尺寸、显示倍率及其用途；初态模板8×8展开必须产生64个独立状态，区域编辑明确显示8×8逻辑像素范围，单像素工具仍只选一个坐标。该约定不增加JSON显示字段，schemaVersion继续为1。

配套256×256示例含65536个可寻址逻辑位置：1:1显示占256×256画面像素，3倍显示占768×768但状态数不变。若768×768画面要求逐点独立，须使用对应逻辑分辨率并重新验证材料、变更及内存预算；仅修改cellSize或去掉网格线不能达成。详见[示例说明](examples/README.md)。

新增验收由M00提供逐像素夹具，M07B-08–11核对纹素、1:1、缩放、配置及动态体边界，M08-09核对单像素操作和保存，M09纳入T1/T6/T8/T9。2026年10月5日独立模块预览已改为逐逻辑像素Point纹理、默认1:1及显式整数倍显示，显示自有256×256、cellSize=0.1配置；已在Editor实际输出验证1倍及3倍无格间缝。M00–M05回归及验收边界见[整改记录](validation/像素粒度-整改与验证.md)。正式渲染、配置预览、旋转查询及Windows Player验收仍待完成。

## 6. 结构、几何与物理

结构规则固定为四邻接且 connectionGroup 相同才连接；木头与混凝土默认同属 building。固定约束只绑定主网格 structure 格；分量只要仍连到一个有效固定格就保留固定。新增主网格材料参加同组连通检查，两个动态体接触不建立连接，动态体与地形接触也不焊接。

初始化、结构材料增删替换及燃尽均触发检查。先找全部分量，再处理每个结果；MinRigidBodyCells=1，所有一格及以上的自由分量都生成刚体。原体剩一个分量保留 BodyId，多分量时撤销旧 BodyId 并分配新 ID，空体撤销。固定点所附格消失时同步撤销约束。

碰撞采用确定性贪心矩形合并：从最小 y/x 的未覆盖格起，先沿 x 扩展连续非空区间，再沿 y 扩展同宽且未覆盖的行，标记后继续。可跨材料种类合并，同一连通体内保持完全覆盖且不覆盖孔洞；矩形之间不重叠。每个矩形对应一个 BoxCollider2D，同体共享一个刚体。静态几何同样按真实占据生成并计入全局形状预算。

质量 M=sum(m_i)，质心 c=sum(m_i*c_i)/M；二维惯量 I=sum(m_i*cellSize^2/6 + m_i*|c_i-c|^2)。使用材料配置的每格质量，不使用矩形数量代替质量。拆分保持剩余格的世界位置，子体线速度为 v+omega×(c子−c原)，角速度继承原值；无额外冲量。

删格、燃尽或替换异材即使只剩一个分量、继续使用原 BodyId，也必须保持剩余格世界位姿，并按新质心应用同一速度场公式 v新=v旧+omega×(c新−c旧)。局部几何原点与质心分开保存，不因重算质心平移材料。内部角速度用弧度／秒，适配器与 Rigidbody2D 的度／秒互转。碰撞更新后关闭自动质量计算，显式设置 mass、centerOfMass、inertia，再恢复连续速度；Unity 提供这些属性的写入接口。[质心接口](https://docs.unity3d.com/6000.3/Documentation/ScriptReference/Rigidbody2D-centerOfMass.html)、[惯量接口](https://docs.unity3d.com/6000.3/Documentation/ScriptReference/Rigidbody2D-inertia.html)。

### 6.1 结构事务

材料修改、全部结果体、碰撞、质量、占据索引及显示关联先准备并校验，成功后共同生效；准备失败不能只留下材料或一部分碎块。旧碰撞必须在后续求解前撤销，不依赖延迟销毁。

事务覆盖一次命令或一个已裁决规则批次，不承诺整个 Tick 和物理求解器可回滚。内部工作变化先于物理落地，对外结果只在 Tick 完整成功后发布。失败后的普通查询禁用，显示停在最后成功版本，诊断保存失败阶段；只允许 Reset／Dispose。

### 6.2 物理推进与水汽暂存恢复

采用独立 Unity 2D 物理场景，由唯一 Host 手动推进，不同时推进默认场景或重复施加重力。动态体使用连续位姿，首版不加渲染插值。

每体 gravityScale=0，适配器在每个子步开始用 Force 模式施加 M×(0,gravityY)，随后模拟 h/N 秒；力不再乘 h 或 N，不改宿主 Physics2D.gravity。该方式用于按世界配置隔离重力，须用自由落体探针核对不同子步数下的积分误差。[Unity AddForce 接口](https://docs.unity3d.com/6000.3/Documentation/ScriptReference/Rigidbody2D.AddForce.html)。

世界四边各生成一个厚度为 cellSize 的静态 BoxCollider2D，放在范围外、内表面与逻辑边界齐平；固定4个形状单独计数，既不消耗材料格，也不参与材料查询。外部写入越界直接拒绝，普通运动由边界碰撞阻挡。

按所有体的预测最大边缘位移选子步数：以线速度、重力在本步的增量和 |omega|×包围半径估算，要求每子步≤cellSize/2，总时长严格等于 stepSeconds。至少一次，最多 maxPhysicsSubsteps 次；超过子步或速度预算时明确 Faulted，不截断速度冒充成功。每子步后再次检查实际位移、速度和完整几何世界边界。

几何接触 epsilon 与物理求解误差分开：前者仍为 1e-4×cellSize，不因求解器提前生成接触而扩大传播或灭火距离。物理后不同归属的真实固体格之间，最小分离平移深度不超过 0.1×cellSize；固体对世界边界检查完整几何超出逻辑矩形的最大距离，同样不得超过 0.1×cellSize，作为首版允许的微穿透预算；超过即 Faulted，不以“任何正面积交叠都失败”判定普通碰撞，也不将此预算用于允许 Spawn 重叠。边界查询仍按逻辑范围返回越界。该预算须在 T5 用平地、角点和高速接触探针验证；Unity contact offset 能在物体仍分离时生成碰撞接触，不能当作实际材料接触的证明。[Unity 接触偏移说明](https://docs.unity3d.com/6000.3/Documentation/ScriptReference/Physics2D-defaultContactOffset.html)。

水和蒸汽不对刚体施加力。运动体读回候选位姿后，真实固体格正方形与活动水汽格有正面积重叠时，按源y/x收集并去重。整批准备“源网格清空＋完整状态进入暂存＋实例映射＋候选位姿”，统一预算预检成功后一次采用，不要求即时找到空位。隐藏记录不参与流动、占据、普通查询、接触和显示，新记录最早下一Tick恢复；暂存材料始终计入总量。

全部物理子步成功后、发布前，按进入Tick、原y/x、稳定记录ID顺序为旧暂存尝试恢复。先试原位置，再做半径不超过fluidDisplacementRadius的四邻接搜索，目标按路径距离、y/x选择；目标须在界内、活动网格为空、最终固体外且未被预留。起点允许被动态固体覆盖，后续路径不得穿最终固体；起点被静态结构覆盖则等待，不穿墙或边界。允许经过活动水汽，但中间格不改动。能放下的记录整批预检后恢复，其余保留；没有目标仍Ready，资源或内部故障仍按合同Faulted。完整时序、寿命、计数和验收见[M06-F01](specs/M06-F01-水汽暂存与恢复.md)。

物理前、每子步暂存前后及最终恢复后的有效水接触均参与熄灭；隐藏锚点不产生接触，已有湿标记本Tick不撤销。物理场景可能已经内部推进，真正故障不承诺回滚物理解算，未校验的候选位姿不用于公开查询或显示。

## 7. 接口、生命周期与错误

Core/Data 保存值类型、材料定义、规则注册及配置校验；Simulation 管理唯一工作状态与调度；Structure 完成连通与提取；PhysicsAdapter 管理 Unity API；Render 消费已提交数据；Editor 与运行时代码分离。ECS 仅是可选游戏接入方式。

| 接口 | 输入与结果 |
| --- | --- |
| Create | 三份配置文本及 origin；返回 World 或带文件/字段/错误码的失败结果；成功 generation 新建、committedTick=0 |
| Enqueue | MaterialCommand：操作、世界矩形、所需 MaterialId、generation；返回递增 CommandToken，不同步推进模拟 |
| Retry | 已取得的 CommandToken；返回原请求 Pending、缓存完成结果或明确错误，不再次入队或执行 |
| Step | 只在 Ready 执行一次固定步长；返回 StepResult、版本及各命令结果，不接受调用方临时改变 h |
| QueryPoint | 世界点；返回唯一 CellHit 或合法空结果，包含基础材料、运行状态及归属 |
| QueryRegion | 世界矩形与调用方缓冲；返回格中心命中列表、requiredCount 与版本 |
| QuerySegment | 两世界端点与调用方缓冲；返回真实格交集，按距离及稳定格键排序 |
| QueryMaterialCounts | 最近成功版本的活动网格/体内、暂存水/蒸汽及逐材料总量；返回不可变值快照，Faulted也不读取失败工作候选 |
| Reset | 使用保留初态重建，generation 增加、Tick=0；清除旧命令和引用 |
| Dispose | 释放世界及临时资源，可重复；之后只返回 Disposed |

普通查询及Remove/Replace/Ignite只处理活动材料，不命中隐藏暂存。Spawn容量包含暂存数量，恢复不覆盖后来生成的材料。诊断按同一版本区分网格、体内、暂存及总量。

CellHit 包含 generation、committedTick、MaterialId、可读状态、ownerKind、BodyId（主网格为0）与局部格坐标。缓冲不足返回 BufferTooSmall 和所需数量，缓冲内容不作为部分成功结果；合法空结果也带版本。读取不分配区块。物理微穿透使一个点命中多个格时，按主网格优先、再 BodyId、局部 y/x 的稳定顺序取首个；区域和线段返回全部实际命中，按格身份去重。

MaterialCommand 支持 Spawn、Remove、Replace、Ignite。世界矩形为有限坐标的左闭右开范围，宽高必须为正、完整范围必须在世界内，不做越界裁切。Spawn 按矩形枚举主网格格中心，包括空格；任何目标已有材料或格正方形与动态固体有正面积重叠，返回 Occupied 并整条拒绝。Spawn 不在动态体局部坐标生成。Remove 空位无变化；Replace 只替换命中的现有材料、跳过空格，并重置新材料状态及撤销原固定标记；Ignite 只影响可燃格。对动态体的 Replace 首版只接受 structure 固体，替换为水汽返回 UnsupportedOperation，避免未定义的旋转落位。无匹配可燃格的 Ignite 返回完成且 affectedCount=0。

每条区域命令先取得完整命中集合并去重，再整体预检及提交。令牌包含 generation 和单调序号。Enqueue 成功分配新令牌，不接受调用方伪造序号；Retry(token) 只读取原请求状态，实现响应丢失后的安全重试。v1 同时最多4096条待执行命令，并缓存最近4096条完成结果；队列满返回 CapacityExceeded 且不分配令牌。缓存淘汰后仍以完成序号水位识别 ResultExpired；从未分配的序号为 InvalidToken，旧 generation 为 StaleGeneration。不同令牌视为不同请求。命令结果描述该命令产生的变化；其后同 Tick 的环境规则仍可进一步改变状态。

Result 包含 status、errorCode、diagnostic；CommandResult 另含 token、affectedCount、提交版本。StepResult 包含成功版本及本步命令结果的只读视图，有效期到下一次 Step／Reset，长期持有须复制。ChangeSet 包含生成、移除、状态改变、归属改变、进入暂存和恢复的关联记录及体创建／撤销、旧新 BodyId 映射；通知中视图仅在回调期间有效。失败 Tick 的命令不能报告为已公开成功：Retry 返回 Faulted 及诊断，不允许重试执行；Reset 清空该 generation 的令牌。查询配置和错误诊断可在 Faulted 读取，普通材料查询不能读取内部未提交工作状态。

以下为拟实现的 C# 入口签名，类型均为上述值数据或结果包装；不是已有源码 API：

```csharp
WorldCreateResult Create(WorldSources sources, Vector2 origin);
EnqueueResult Enqueue(in MaterialCommand command);
CommandResult Retry(in CommandToken token);
StepResult Step();
PointQueryResult QueryPoint(Vector2 point);
QueryResult QueryRegion(in WorldRect region, Span<CellHit> destination);
QueryResult QuerySegment(Vector2 start, Vector2 end, Span<CellHit> destination);
WorldResult Reset();
WorldResult Dispose();
```

WorldSources 持有三份文本及诊断用文件名；WorldRect 为 Min/Max 两点；MaterialCommand 只在 Spawn／Replace 时携带非零 MaterialId，其他操作为0。WorldCreateResult 成功才携带可用的世界实例。所有公开操作限所属主线程；世界实例的 Dispose 是显式返回 WorldResult 的关闭方法，如另适配 IDisposable，则将其无返回值方法转发到同一释放逻辑。

统一错误至少包含 InvalidConfig、InvalidArgument、UnsupportedVersion、UnknownMaterial、UnknownRule、IncompatibleRule、OutOfBounds、Occupied、CapacityExceeded、UnsupportedOperation、InvalidToken、ResultExpired、StaleGeneration、BufferTooSmall、Busy、NotReady、Faulted、Disposed。给出具体文件/字段或作用目标；错误不能只返回 false 或静默忽略。

自动与手动驱动互斥，Host 自动步长必须与创建配置一致，不修改宿主全局设置。规则和求解阶段禁止外部回调或查询重入；提交通知允许查询与入队，新命令下一步执行。通知内 Step／Reset／Dispose 返回 Busy，生命周期请求可交 Host 延后执行；订阅异常记录但不撤销已提交 Tick。

Create的Tick0暂存为空；Reset清理旧暂存并从编辑初态重建，退出试玩/Dispose释放暂存集合及缓冲，scene.json仍不保存运行状态。Reset 失败进入 Faulted，不恢复旧世界；Dispose 后不能 Reset。所有 NativeArray、纹理、Material、Mesh、物理场景、临时几何与工作缓冲都有明确拥有者，初始化失败按拥有者释放。显示与查询在同 generation/committedTick 上核对，帧末检查 GPU 上传版本，不要求任意调用瞬间 GPU 同步。
