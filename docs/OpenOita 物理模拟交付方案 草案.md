## 目标与约束

交付面向 Unity PC 的材料世界组件。策划可绘制场景，运行后由系统完成逐像素材料变化、结构识别、自动脱落与拆分、刚体运动。角色控制、武器玩法、生命伤害、AI及任务仍由游戏负责。

首版硬性链路：**材料改变 → 连接与固定检查 → 识别全部断开部分 → 自动提取或拆分 → 继续物理运动。**

输入是整个场景的材料布局和固定约束，不要求登记木板或碎块。外部只提交材料作用，不负责判断、指定或触发哪块脱落。已有动态体被再次切断后，也必须自动拆分。

### 材料规则

燃烧规则适用于木头等可燃材料，已确认纳入首版：可点燃、传播、烧损，遇水熄灭，燃尽消失；不产生烟或灰（含对应效果），不模拟耗氧。

规则采用以下实现默认值，详细阶段、竞争和边界处理以[实现方案](<D:/work/Project/OpenOita/docs/OpenOita 初步实现方案 草案.md>)为准：

| 规则 | 默认行为 |
| --- | --- |
| 水移动 | 每 2 Tick 尝试下、斜下、横向移动一格；只进入空格，边界阻挡，不穿角，不与蒸汽交换位置。 |
| 蒸汽移动与寿命 | 每 3 Tick 尝试上、斜上、横向移动一格；只进入空格，边界阻挡，不穿角；默认 200 Tick 后自然消散。 |
| 燃烧 | 木头初始燃料 250 个燃烧 Tick，每 10 个燃烧 Tick 向四邻接传播；新点燃格从下一 Tick 更新。 |
| 遇水熄灭 | 水的四面接触判定先于传播和烧损，水不消耗、不蒸发；停止燃烧但保留剩余燃料，之后可再次点燃。 |
| 烧损与燃尽 | 烧损记录剩余量，燃尽前保留整格质量和碰撞；燃尽移除该格并进入完整结构更新链。 |

固定步长默认 0.02 秒，格长默认 0.1。蒸发、冷凝、浮力及其他新增反应不在当前规则集内，不能由遇水熄灭默认推导。

燃烧状态是规则执行的附加记录，火焰是该状态的附着视觉表现，不作为独立材料。尚未燃尽的燃烧物保留原材料身份，状态及附着效果随材料运动和拆分；具体状态与显示合同见“配置与接入合同”。

程序预算以 Skymu 主力为基础；黄彦楷、刘荣文、Va1otus 为可调配支援，未认领时间不计入固定产能。用户目标仍为10月15日开发完成、10月19日最终包；新增范围须重估后倒排，不据此承诺日期。

## 组件与绘制工具

本轮以 Unity 编辑器 Scene 视图绘制为设计基线，运行时画笔尚未确认。首版组件提供：

- 世界范围、格子尺寸与材料配置入口。
- 材料选择、画笔、擦除、网格预览和固定区域标记。
- 初始布局与固定约束的保存、重开和继续编辑。
- 从绘制结果初始化模拟；试玩中的破坏默认不覆盖初始布局。

笔画不决定物体边界：一笔材料可断成多个部分，多笔材料也可按连接规则成为整体。策划无需编写逐次释放或拆分脚本。

首版采用自定义 Scene 画笔。地图保存初态 `cells`、`fixedCells`、`initialBurning` 及材料集标识，不保存运行时 `BodyId`；进入运行时建立副本。撤销重做、区域填充、图片导入和图案笔刷属于可选扩展，不阻塞当前工具基线。

## 模拟与架构

采用“逐像素材料内核 → 内部结构系统 → 动态材料体 → Unity 2D 刚体适配”的流程。对象层 ECS 仅为可选玩法组织方式，不是物理结构识别的前提。

- 材料内核按区块保存逐格状态；区块不构成物体边界。
- 结构系统按四邻接及相同 `connectionGroup` 建立连接；木头与混凝土均属 `building`。固定约束绑定具体材料格，删格同时撤销对应固定约束；动态体碰撞不建立连接。
- 失去固定连接的部分自动提取；动态体保留局部材料，可逐格破坏并再次拆分。
- 每个断开分量均保留为刚体，`MinRigidBodyCells=1`，单格碎片也不得丢弃或转散粒。碰撞使用贪心矩形精确覆盖实际材料，无几何简化误差；全量连接检查覆盖跨区块分量。
- 刚体适配更新形状、质量、质心与惯量，并为拆分部分继承运动状态。核心不直接调用 Unity 物理 API，专属物理场景由单一驱动推进。
- 材料状态是唯一事实来源；碰撞、占据、查询和显示均由其派生，并在约定提交阶段保持一致。

默认世界 256×256 格、区块边长 128，主网格、动态体与暂存合计最多 65536 个材料格；最多 64 个动态体，每体最多 256 个矩形、静态与动态材料总计最多 4096 个碰撞形状，世界边界另设 4 个碰撞形状并单独计入预算；每 Tick 最多 65536 项材料变更。外部命令超限整条拒绝，自动规则超限进入故障状态并保留材料。独立 Unity 2D 场景最多 8 个子步；运动体覆盖水、蒸汽时整批暂存，最早下一Tick尝试原格/附近恢复；没有合法落位继续等待且Ready，禁止覆盖或丢料。暂存蒸汽每Tick寿命照常扣减，实际暂存/恢复资源故障仍按合同处理；详见M06-F01。

具体数据与时序见[技术初案](<D:/work/Project/OpenOita/docs/OpenOita 技术初案 评审稿.md>)；模块与探针见[实现方案](<D:/work/Project/OpenOita/docs/OpenOita 初步实现方案 草案.md>)。

## 首版范围与分阶段边界

首版包含组件绘制与保存、配置初始化、固定步长、材料作用、自动结构处理、动态体持续破坏、查询与通知、独立 PC 包及一次真实游戏接入。

开发可分阶段验证网格、预置体释放、连通检查和几何重建；旧 V0/R 仅作内部实验参考。预置木板下落与旋转只能证明求解器接入，不能代替首版验收。

可以缩小探针场景，先完成直接破坏闭环，再接入已确认的材料与燃烧规则。探针可使用功能子集，完整首版仍覆盖四种基础材料、燃烧规则、附加状态及附着效果；不能将燃烧整体默认归入后续版本。不得把自动识别、全部分量处理或动态体再拆分移至首版之后。

不包含弯曲、弹性变形、应力传播与承载过载断裂。复杂流体双向作用、浮力、角色推挤、大规模气体与多房间传播可后续评审。

技术实现以本轮版本化材料、规则、场景及验收默认值为基线，可据此编码和探针验证，不再等待策划逐项决定字段或算法。策划可反馈体验与扩展需求，涉及当前范围之外的反应另行确认；Skymu 按实际探针结果和模块范围重新估时，不把文档中的默认值当作已测结论。

## 配置与接入合同

全部材料从一个 `materials.json` 加载，使用 `schemaVersion=1` 与 `materialSetId`；地图核对材料集标识及全部材料引用。`kind` 只分类，`tags` 显式启用已注册规则，加载时转换为 `RuleId`、`ulong` 位掩码及共享参数；格子只存材料 ID 与实例状态，不逐格保留字符串标签。新增材料可组合已有规则，新增规则行为仍需实现 C#。未知键、未知标签及非法范围拒绝加载，完整格式、样例与注册合同见[实现方案](<D:/work/Project/OpenOita/docs/OpenOita 初步实现方案 草案.md>)、[材料样例](D:/work/Project/OpenOita/docs/examples/materials.json)与[材料 Schema](D:/work/Project/OpenOita/docs/schemas/materials.schema.json)。旧 stone／sand 资产保留，不悄悄改变旧 ID 的含义。

公开接口覆盖创建、销毁、重置、步进、坐标转换、点/区域/线段查询、材料作用和变化通知。对世界区域提交作用时，系统定位主网格及动态体材料，调用方无需先选择将要脱落的物体。

同一材料只归主网格、一个材料体或一条水汽暂存记录所有，同一命令不重复执行。资源或几何准备失败时，材料与碰撞不得部分提交；应提供可定位的错误和恢复策略。外部不能直接修改内部数组。

剩余燃料随材料搬运、提取与拆分；熄灭只关闭正在燃烧标志及附着火焰，不恢复已烧损燃料。燃尽前质量和碰撞保持整格值，燃尽移除进入材料事务，同步更新连接、固定、拆分、质量与碰撞；其他移除／替换及 Reset 也不得残留错误状态或效果。

独立包所需配置须走运行时可用的加载路径；完成初始化、销毁、重置、重复进入及失败场景的验证。

## 验收

以下 T1–T9 全部属于首版验收，当前均未执行。具体初态、命令步骤、数值预期与固定负载以[实现方案](<D:/work/Project/OpenOita/docs/OpenOita 初步实现方案 草案.md>)为主合同；材料和火焰仅能显示不代表通过。

| 编号 | 场景与要求 |
|---|---|
| T1 绘制保存 | 不写脚本即可绘制、擦除、标记固定区域、保存重开；试玩不污染初始布局，笔画不决定物体边界。 |
| T2 配置初始化 | 编辑器与独立 PC 包从单个 materials.json 加载四种材料；版本、材料集、引用、未知键／标签及参数错误拒绝整个配置，不留半初始化状态。 |
| T3 固定与连通 | 验证跨区块连接；保留其他固定连接时不误脱落；接触不自动建立连接。 |
| T4 多块脱落 | 未预登记物体的场景中，一次破坏产生多个断开部分，全部按规则处理并继续运动。 |
| T5 动态编辑再拆分 | 运动体可逐格破坏；切断后生成独立部分，运动状态合理，后续仍可继续破坏。 |
| T6 状态一致 | 核对材料归属与数量、坐标转换、查询、碰撞和显示；明确消耗或转化之外不重叠持有、不凭空增减。 |
| T7 故障与生命周期 | 创建、重置、销毁及重复操作稳定；重复、非法命令与容量失败行为符合合同，无残留物理体。 |
| T8 性能与接入 | 在开发机记录固定负载下的完整 Step、独立包回归及一次公开接口真实游戏接入；按下述拟定预算判断，不等同发布最低配置保证。 |
| T9 首版材料与燃烧 | 按规则默认值验证水移动、蒸汽移动及消散、点燃／传播／烧损／水灭火／燃尽；检查新点燃下步更新、熄灭保留燃料、再次点燃、燃尽结构更新；检查旋转与拆分后的状态和火焰归属，无烟、灰和耗氧，移除／替换／Reset 无残留。 |

测试记录区分通过、失败、未测，附配置版本、场景和复现步骤。单格碎片、全部分量处理及容量失败路径均须实测，技术默认值已写入文档不代表相关验收通过。

性能首先以开发机作为工程基线，记录实际机器型号、构建与后端，不虚填硬件。固定负载的拟定目标为：稳定完整 Step 的 p95≤10 ms、p99≤16 ms；集中破坏 Step 峰值≤50 ms；稳定 Step 的 GC Alloc=0；模拟专属 CPU 内存峰值≤256 MiB。以上是待测目标，不是实测保证；记录完整链路、连通检查、几何重建和多碎块峰值，不把结构开销归因于标签判断。发布最低配置另定；若探针不能达标，调整方案或明确修订预算，不事后倒推通过标准。
